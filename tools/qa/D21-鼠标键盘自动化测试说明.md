## 二、三个根因（2026-09-05 实测定位，此前「鼠标不通键盘通」的完整解释）

### 1. 坐标单位：CGEvent 用 point，不是物理像素 ❗核心
- **实测**：注入 mouseMoved(1740,458) 后读回 WindowServer 真实光标 = (1740,458)——CGEvent 坐标**按 point 原样存储**（全局显示坐标，左上原点），Retina scale 不参与
- 旧公式「screen = win_origin物理像素 + rect_center逻辑 × scale」在 scale=2 下放大 2 倍，点击落在窗口右侧 520pt 远的空白处
- **正确公式**：`screen_point = CGWindowList窗口bounds左上(point) + 标题栏高 + rect中心(逻辑point)`，标题栏高 = bounds.h − 内容高(win-frame size.y/scale)，全部实测值
- 键盘事件无位置概念，故不受影响——「键盘通、鼠标不通」的主因

### 2. ctypes 声明：CGPoint 按值传递，非指针 ❗
- C 签名 `CGEventCreateMouseEvent(source, type, CGPoint mouseCursorPosition, button)` 的第三个参数是 **CGPoint 按值**（两个 double 走寄存器），不是 `CGPoint*`
- 旧 ctypes 声明成 `c_void_p` + `ctypes.pointer(pt)` → 函数读到寄存器垃圾，实测光标被送到 (0,0)/nan
- 修复：`argtypes = [c_void_p, c_uint32, _CGPoint, c_uint32]`，调用传 `_CGPoint(x, y)`

### 3. 窗口遮挡：必须 AX raise 到最前端 ❗
- `NSRunningApplication.activateWithOptions_(NSApplicationActivateIgnoringOtherApps)` 只激活应用进程，**不保证窗口在 z 序最前**——被其他窗口（如全屏 Hermes）遮住时点击落在遮挡窗口上
- 修复：注入前执行 `osascript -e 'tell application "System Events" to tell (first process whose unix id is <pid>) to perform action "AXRaise" of window 1'`
- 附加（deskflow issue 印证，macOS 26+）：synthetic 点击不激活非活动窗口，所以 activate 也必需

## 三、主脚本运行示例

```bash
# 启动 demo（日志重定向）
cargo run -p rgui --features window --example window_demo 2>/tmp/rgui_demo.log &

# 鼠标点击断言（自动：定位窗口→激活→raise→注入→增量断言）
python3 tools/qa/rgui_input_test.py --log /tmp/rgui_demo.log \
    --inject-clicks accordion wabadge --expect "[action] toggle" "[action] badge_click"

# 键盘 Tab 焦点断言
python3 tools/qa/rgui_input_test.py --log /tmp/rgui_demo.log --tab 2 --expect "[focus] Tab"

# dry-run（不注入，只解析+换算）
python3 tools/qa/rgui_input_test.py --log /tmp/rgui_demo.log --inject-clicks accordion --dry-run
```
