## 0. D6 验收目标（tasks.md D6 §116-131）

D5 的 from_view 是占位（`red_filled_rect` 绕过、只认 Color、尺寸固定、无布局/文本）。D6 目标：

1. `from_view(WidgetView)` 补全：递归 WidgetView 树 → SceneGraph/draw 指令；处理**完整 Props**（Color/Size/Str/Int/WidgetId 等，不再静默忽略）；文本路径接入（真实 glyph atlas/shaper）
2. **布局应用**：from_view 生成 SceneGraph 时调用 LayoutEngine（从 WidgetView 提取布局信息 → Taffy → 实际 bounds → 对应 draw），让布局真正作用于渲染
3. 真实端到端：真实 WidgetView（布局+props+文本）→ from_view → SceneGraph → 离屏渲染 → **像素级断言**（替换 D5 手工 rect）

## 2. from_view 对完整 Props 的处理（A 层核心）

**目标**：`SceneGraph::from_view` 不再只认 Color，完整映射所有 `PropValue` 变体。

| ID | 用例 | Arrange | Act | Assert |
|----|------|---------|-----|--------|
| FV1 | Color → FillRect | view.props = Color(r,g,b) | `from_view` | 产生 1 条 FillRect，color==该颜色 |
| FV2 | Str → DrawText | view.props = Str("hi") | `from_view` | 产生 DrawText，text=="hi"，size>0 |
| FV3 | Size → bounds | view.props = Size(100,40) + 布局/尺寸 | `from_view` | FillRect 的 width/height==100/40（不再固定） |
| FV4 | Int → DrawText? | view.props = Int(7)（如字号/顺序） | `from_view` | 映射到某 draw 属性（text 或 size），不静默丢 |
| FV5 | WidgetId → 透明/占位 | view.props = 含 WidgetId | `from_view` | 不 panic；按 dev 契约映射（key/标记），不丢 |
| FV6 | Unit 节点 | view.props = Unit | `from_view` | 不产生 draw（容器），但仍递归子节点 |
| FV7 | 混合嵌套 | 容器(Unit) 含 Color 子 + Str 子 | `from_view` | draw 顺序：父(0)+子(Color)+子(Str)，children 顺序一致 |
| FV8 | 完整 Props 无忽略 | 同时含 Color+Str+Int 的节点 | `from_view` | 每种 PropValue 都被处理（无静默忽略——D5 缺陷） |

> **D5 已知缺陷（D6 必修）**：from_view 当前只匹配 `PropValue::Color`，其余（Size/Str/Int/WidgetId）静默忽略。FV2-FV8 直接针对此缺口。

## 3. 布局从 WidgetView 实际作用于渲染（A 层，bounds 正确性）

**目标**：from_view 调用 `core::layout::LayoutEngine`，从 WidgetView 布局信息得到**实际 bounds**，draw 指令用真实 bounds 而非固定 100x40。

| ID | 用例 | Arrange | Act | Assert |
|----|------|---------|-----|--------|
| L1 | 固定尺寸布局 | view 携带 width=100,height=40 布局信息，容器 200x200 | `from_view` | FillRect width/height==100/40，非固定占位 |
| L2 | 子节点垂直/顺序排布 | 容器 + 2 子节点(各固定尺寸) | `from_view` | 子 draw 的 y 按布局递增（非固定 40*i），坐标正确 |
| L3 | bounds 来自 LayoutResult | view 含布局 result | `from_view` | draw 的 rect.x/y/w/h 与布局 result 一致 |
| L4 | 超边界 clamp/不越界 | 子节点 > 容器 | `from_view` | draw bounds ≤ 容器（或按 dev 布局 clamp），不 panic |
| L5 | 布局引擎被真实调用 | 需布局的 view | `from_view` | 内部调用 `LayoutEngine::compute`/`to_taffy_style`（探测：布局结果影响 draw，而非硬编码） |
| L6 | 无布局信息时兜底 | 无宽高 | `from_view` | 用默认/兜底尺寸，不 panic、不 NaN |

> 参照：`core::layout::LayoutEngine::compute(container: Size, children: &[Size]) -> LayoutResult`（core/src/layout/mod.rs）；`LayoutStyle{width,height,grow}`（mapping.rs）。

## 4. 真实 end-to-end（WidgetView → SceneGraph → 离屏渲染 → 像素级，B 层）

**目标**：用真实 WidgetView（含布局+props+文本）替换 D5 的手工 `red_filled_rect` 测试。

| ID | 用例 | Arrange | Act | Assert |
|----|------|---------|-----|--------|
| E2E1 | 真实 Color view 渲染像素 | Color(r,g,b) view → from_view → render_offscreen(64,64) | 读回中心像素 | 中心像素≈Color(r,g,b)（容差内，替换 red_filled_rect） |
| E2E2 | 文本 view 渲染非空像素 | Str view → 渲染 | 读回文本区 | 文本覆盖区有非背景像素（≠背景色） |
| E2E3 | 多节点布局像素验证 | 容器 + 2 子（不同颜色）→ 渲染 | 采样各子区域中心 | 各子区域中心≈各自颜色（验证布局 bounds 真实作用于渲染） |
| E2E4 | 背景透明/默认 | 无背景 view → 渲染 | 空白区 | 空白区 alpha=0（或默认背景） |
| E2E5 | 尺寸边界 | 0 或极大尺寸 view | 渲染 | 不 panic |
| E2E6 | 替换清单确认 | 对比 D5 offscreen.rs | 巡检 | **不再有 red_filled_rect / 手工矩形绕过的用例残留**（P1-1 清除） |

> ⚠️ E2E 是 D6 核心验收（tasks.md §126"像素级验证替换手工 rect"）。E2E6 专门核对 P1-1 是否真正清除。
