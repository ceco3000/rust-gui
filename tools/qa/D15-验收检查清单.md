## 0. D15 验收目标（tasks.md D15）

scale_factor/DPI 换算：hit-test / 焦点 / 坐标在高分屏、多显示器下正确。reviewer 多次点名（D11 P2、D5 未实现项）。

**问题背景**：winit `WindowEvent::CursorMoved { position }` 的 `position` 是**物理坐标**（随 scale_factor 变，Retina 屏 scale=2）。而 `HitRegion`（如 `Rect::new(0,0,340,44)`）按**逻辑坐标**定义。若不换算，高分屏下 hit-test 错位。

## 2. hit-test 坐标影响核对（总监重点）

> 这是本阶段**核心核对点**：scale_factor 改动直接影响 hit-test 正确性。

**核对逻辑**：
- 换算前（现状）：`cursor = (position.x as f32, position.y as f32)`——物理坐标直接喂 hit_test
- 换算后（D15 目标）：`cursor = (position.x / scale_factor, position.y / scale_factor)`——逻辑坐标喂 hit_test
- 验证：在 Retina 高分屏（scale=2）下，点击逻辑坐标 (50,20)（应在 Accordion 标题区）时，物理 position 是 (100,40)；若直接 (100,40) hit_test 会命中错误区域或越界。换算后 (50,20) 正确命中。

**加验证**：建议 dev 补一个**纯函数**（如 `to_logical(physical_pos, scale) -> logical_pos`）+ 单测，或直接在 demo CursorMoved 用 scale_factor 换算，并用尺寸实测核对。
