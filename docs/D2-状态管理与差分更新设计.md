## 1. 设计目标与范围

### 1.1 本文档解决什么问题

1. 定义 `StateStore` 的完整字段、访问模式和并发安全策略
2. 明确三类状态（持久态、实例态、缓存态）的分层契约和访问权限
3. 设计 `WidgetView` diff 算法，产出 `Patch` 列表
4. 定义状态订阅模型：widget 间状态依赖的自动追踪和脏标记传播
5. 定义快照格式、持久化协议和 schema 迁移机制

### 1.2 不在本文档范围内

- 渲染缓存（`RenderLayoutCache`）的内部结构（见 D3）
- 样式属性的计算与合并（见 D4）
- 无障碍树的构建（见 D6）

### 1.3 设计原则

1. **分层隔离**：持久态、实例态、缓存态严格分离，互不交叉
2. **自动依赖追踪**：widget 间状态读取自动建立订阅，无需手动声明
3. **增量更新**：仅 dirty widget 重新 view/diff/layout/paint
4. **快照只捕获持久态**：实例态和缓存态可从持久态重建

### 2.2 各层详细契约

#### 持久态（Persistent State）

| 属性 | 说明 |
|------|------|
| **持有者** | 应用代码（通过 `WidgetSpec::State`） |
| **生命周期** | 组件创建 → 组件卸载 |
| **序列化** | 是（通过 `erased_serde::Serialize`，见 D1 §2.4 PersistState trait 完整定义） |
| **快照** | 参与 |
| **迁移** | 支持（通过 `schema_name` + `schema_version`） |
| **访问控制** | 自身可写，他人只读 |
| **约束** | 不含 GPU/平台/文件句柄、不含 `Rc`/`RefCell`（需 `Send + Sync`） |

#### 实例态（Instance State）

| 属性 | 说明 |
|------|------|
| **持有者** | 框架运行时 |
| **生命周期** | 组件挂载 → 组件卸载 |
| **序列化** | 否 |
| **快照** | 不参与 |
| **内容** | 焦点状态、悬停状态、命中测试矩形、节点句柄 |
| **访问控制** | 仅框架内部（`pub(crate)`） |

```rust
/// 实例态：框架运行时持有的 per-widget 交互状态。
///
/// 应用代码不应直接访问此结构。焦点和悬停状态通过
/// UpdateContext::focus / UpdateContext::hover 提供只读访问。
#[derive(Debug, Clone)]
pub(crate) struct InstanceState {
    /// 当前是否有键盘焦点
    pub focused: bool,

    /// 当前是否被鼠标悬停
    pub hovered: bool,

    /// 命中测试矩形（窗口坐标），由布局引擎在每次布局后更新。
    /// 用于判断输入事件（鼠标点击、触摸等）是否落在本 widget 范围内。
    pub hit_test_rect: Rect,

    /// widget 在 retained tree 中的节点句柄
    pub node_handle: NodeHandle,

    /// 滚动偏移（用于滚动容器）
    pub scroll_offset: Point,
}
```

#### 缓存态（Render & Layout Cache）

| 属性 | 说明 |
|------|------|
| **持有者** | 框架运行时 |
| **生命周期** | 组件挂载 → 组件卸载 |
| **序列化** | 否 |
| **快照** | 不参与 |
| **内容** | 布局结果（Taffy 输出）、字形 Atlas UV 坐标、GPU 纹理 ID |

## 3. StateStore 完整数据结构

### 3.1 结构定义

```rust
use rustc_hash::{FxHashMap, FxHashSet};

/// 全局状态存储。
///
/// # 线程安全
///
/// StateStore 自身为 `!Send + !Sync`——它由主线程持有。
/// 后台线程（layout、paint）通过只读快照或消息传递访问数据。
///
/// # 使用 FxHashMap/FxHashSet 的理由
///
/// WidgetId 是 u64，FxHash（基于 fxhash）对整数键的哈希速度远优于 SipHash（标准 HashMap）。
/// StateStore 存取在每帧热路径上，哈希性能直接影响帧率。
/// 基准测试（V5）显示 FxHashMap<u64, T> 比 HashMap<u64, T> 插入快约 2.5×，查找快约 1.8×。
pub struct StateStore {
    /// 持久业务状态（可快照、可迁移）。
    ///
    /// 键为 WidgetId，值为类型擦除的 PersistState。
    /// 使用 Box<dyn PersistState> 而非泛型，使不同 WidgetSpec 的状态可共存。
    persistent: FxHashMap<WidgetId, Box<dyn PersistState>>,

    /// 实例态（交互状态）。仅框架内部访问。
    instance: FxHashMap<WidgetId, InstanceState>,

    /// 渲染与布局缓存。仅框架内部访问。
    caches: FxHashMap<WidgetId, RenderLayoutCache>,

    /// 脏标记集合。包含本帧需要重新 view/layout/paint 的 widget ID。
    dirty: FxHashSet<WidgetId>,

    /// 订阅关系。
    /// 键 = 被读取的 widget ID，值 = 读取者的订阅信息列表。
    subscriptions: FxHashMap<WidgetId, Vec<Subscription>>,

    /// WidgetId 分配器（单调递增）。
    next_id: u64,
}

/// 订阅记录：widget A 读取了 widget B 的状态。
#[derive(Debug, Clone)]
pub struct Subscription {
    /// 读取者（订阅者）的 WidgetId
    pub subscriber: WidgetId,

    /// 订阅的生命周期类型
    pub lifetime: SubscriptionLifetime,
}

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum SubscriptionLifetime {
    /// 持久订阅：跨帧保持（默认），在 update() 中通过 StoreAccessMut::read() 建立
    Persistent,

    /// 临时订阅：仅本帧有效，在 view() 中通过 ViewContext 间接读取时建立
    Ephemeral,
}
```

### 3.2 WidgetId 分配

> **类型定义**：`WidgetId` 在 D1 §3.3 已完整定义（`WidgetId(NonZeroU64)`，范围 1..=u64::MAX，0 为无效标识），此处不再重复定义。

```rust
impl StateStore {
    /// 分配新的 WidgetId。
    ///
    /// 使用单调递增计数器，确保全局唯一。WidgetId 从 1 开始分配
    /// （0 为 NonZeroU64 预留的无效标识）。
    pub(crate) fn allocate_id(&mut self) -> WidgetId {
        self.next_id += 1;
        WidgetId(NonZeroU64::new(self.next_id).expect("WidgetId 溢出"))
    }
}
```

### 3.3 生命周期方法

```rust
impl StateStore {
    /// 创建空的 StateStore。
    pub fn new() -> Self {
        StateStore {
            persistent: FxHashMap::default(),
            instance: FxHashMap::default(),
            caches: FxHashMap::default(),
            dirty: FxHashSet::default(),
            subscriptions: FxHashMap::default(),
            next_id: 0,
        }
    }

    /// 插入持久状态（仅框架内部使用，由 diff patch 过程调用）。
    pub(crate) fn insert_persistent(
        &mut self,
        id: WidgetId,
        state: Box<dyn PersistState>,
    ) {
        // 不变式 6：断言 WidgetId 不冲突
        debug_assert!(
            !self.persistent.contains_key(&id),
            "WidgetId {:?} 已存在，不可重复插入",
            id
        );
        self.persistent.insert(id, state);
    }

    /// 移除 widget 的所有状态。
    pub(crate) fn remove(&mut self, id: WidgetId) {
        self.persistent.remove(&id);
        self.instance.remove(&id);
        self.caches.remove(&id);
        self.dirty.remove(&id);
        self.subscriptions.remove(&id);
        // 移除其他 widget 对此 widget 的订阅
        for subs in self.subscriptions.values_mut() {
            subs.retain(|s| s.subscriber != id);
        }
    }

    /// 标记 widget 为 dirty。
    pub(crate) fn mark_dirty(&mut self, id: WidgetId) {
        self.dirty.insert(id);
    }

    /// 传播 dirty 标记到所有订阅者。
    /// 
    /// 使用 `visited` set 防止循环订阅导致无限递归。
    pub(crate) fn propagate_dirty(&mut self, id: WidgetId) {
        let mut visited = std::collections::HashSet::new();
        self.propagate_dirty_inner(id, &mut visited);
    }

    fn propagate_dirty_inner(&mut self, id: WidgetId, visited: &mut std::collections::HashSet<WidgetId>) {
        if !visited.insert(id) {
            return; // 已访问过，跳过（防止循环订阅无限递归）
        }
        if let Some(subscribers) = self.subscriptions.get(&id) {
            for sub in subscribers {
                self.dirty.insert(sub.subscriber);
                self.propagate_dirty_inner(sub.subscriber, visited);
            }
        }
    }

    /// 清除本帧的脏标记（在帧结束时调用）。
    pub(crate) fn clear_dirty(&mut self) {
        self.dirty.clear();
    }

    /// 获取当前 dirty 集合。
    pub fn dirty_widgets(&self) -> &FxHashSet<WidgetId> {
        &self.dirty
    }
}
```

## 4. StoreAccess / StoreAccessMut 详细 API

### 4.1 StoreAccess（只读访问）

```rust
/// 只读状态访问句柄。
///
/// # 生命周期
///
/// `'a` 绑定到当前帧的借用范围。StoreAccess 不能在帧之间保存。
pub struct StoreAccess<'a> {
    persistent: &'a FxHashMap<WidgetId, Box<dyn PersistState>>,
    instance: &'a FxHashMap<WidgetId, InstanceState>,
    /// 当前正在读取的 widget ID（用于订阅追踪）
    current_reader: WidgetId,
    /// 本帧新建立的订阅（出借范围后提交到 StateStore）
    new_subscriptions: &'a mut Vec<(WidgetId, Subscription)>,
}

impl<'a> StoreAccess<'a> {
    /// 创建只读访问句柄（仅框架内部使用）。
    pub(crate) fn new(
        persistent: &'a FxHashMap<WidgetId, Box<dyn PersistState>>,
        instance: &'a FxHashMap<WidgetId, InstanceState>,
        current_reader: WidgetId,
        new_subscriptions: &'a mut Vec<(WidgetId, Subscription)>,
    ) -> Self {
        StoreAccess { persistent, instance, current_reader, new_subscriptions }
    }

    /// 读取自身的持久状态。
    ///
    /// # 类型参数
    ///
    /// `T`: 自身的 PersistState 类型。如果类型不匹配，返回 None。
    /// 类型不匹配表示严重错误（StateStore 中的状态类型与 WidgetSpec::State 不一致）。
    pub fn state<T: PersistState>(&self, self_id: WidgetId) -> &T {
        self.persistent
            .get(&self_id)
            .and_then(|boxed| (**boxed).as_any().downcast_ref::<T>())
            .expect("StateStore: 持久状态类型不匹配——这表示框架内部错误")
    }

    /// 读取其他 widget 的持久状态。
    ///
    /// 调用此方法自动建立从 current_reader 到 target_id 的订阅。
    /// 当 target_id 的状态被修改时，current_reader 自动标记 dirty。
    ///
    /// # 返回
    ///
    /// `Some(&T)` 如果 target_id 存在且类型匹配，`None` 如果 target_id 不存在或类型不匹配。
    pub fn read<T: PersistState>(&mut self, target_id: WidgetId) -> Option<&T> {
        let state = self.persistent
            .get(&target_id)
            .and_then(|boxed| (**boxed).as_any().downcast_ref::<T>())?;

        // 建立订阅
        self.new_subscriptions.push((target_id, Subscription {
            subscriber: self.current_reader,
            lifetime: SubscriptionLifetime::Persistent,
        }));

        Some(state)
    }

    /// 读取实例态（仅框架内部使用）。
    pub(crate) fn instance_state(&self, id: WidgetId) -> Option<&InstanceState> {
        self.instance.get(&id)
    }
}
```

### 4.2 StoreAccessMut（可变访问）

```rust
/// 可变状态访问句柄。
///
/// 在 `update()` 中传递给组件。调用者只能修改自身的持久状态。
/// 对其他 widget 的状态只能读取（通过 `read()`）。
pub struct StoreAccessMut<'a> {
    persistent: &'a mut FxHashMap<WidgetId, Box<dyn PersistState>>,
    /// 当前 widget ID（调用者自身）
    self_id: WidgetId,
    /// 新建立的订阅
    new_subscriptions: Vec<(WidgetId, Subscription)>,
}

impl<'a> StoreAccessMut<'a> {
    /// 创建可变访问句柄（仅框架内部使用，在 `update()` 调用前构造）。
    pub(crate) fn new(
        persistent: &'a mut FxHashMap<WidgetId, Box<dyn PersistState>>,
        self_id: WidgetId,
    ) -> Self {
        StoreAccessMut { persistent, self_id, new_subscriptions: Vec::new() }
    }

    /// 获取自身的可变持久状态。
    ///
    /// 调用此方法后，框架自动标记 self_id 为 dirty。
    pub fn state_mut<T: PersistState>(&mut self) -> &mut T {
        self.persistent
            .get_mut(&self.self_id)
            .and_then(|boxed| (**boxed).as_any_mut().downcast_mut::<T>())
            .expect("StoreAccessMut: 持久状态类型不匹配——这表示框架内部错误")
    }

    /// 读取其他 widget 的持久状态（只读）。
    ///
    /// 调用此方法自动建立从 self_id 到 target_id 的订阅。
    pub fn read<T: PersistState>(&mut self, target_id: WidgetId) -> Option<&T> {
        let state = self.persistent
            .get(&target_id)
            .and_then(|boxed| (**boxed).as_any().downcast_ref::<T>())?;

        self.new_subscriptions.push((target_id, Subscription {
            subscriber: self.self_id,
            lifetime: SubscriptionLifetime::Persistent,
        }));

        Some(state)
    }

    /// 消费句柄，返回本帧新建立的订阅列表。
    pub(crate) fn finish(self) -> Vec<(WidgetId, Subscription)> {
        self.new_subscriptions
    }
}
```

```rust
// 典型 update() 中的使用模式
impl WidgetSpec for DataGrid {
    fn update(
        &self,
        msg: Self::Message,
        state: &mut Self::State,
        ctx: &mut UpdateContext,
    ) {
        match msg {
            DataGridMessage::SortBy(column) => {
                // 修改自身状态
                state.sort_column = column;
                state.sort_direction = state.sort_direction.toggle();
                state.sorted_rows = sort_rows(&state.rows, column, state.sort_direction);

                // 读取其他 widget 的状态（自动建立订阅）
                if let Some(filter_state) = ctx.store.read::<FilterState>(filter_widget_id) {
                    state.active_filter = filter_state.current_filter.clone();
                }
            }
            DataGridMessage::CellEdited(row, col, value) => {
                state.rows[row].cells[col] = value;
                // 发送事件到父组件
                ctx.event_sender.send_to_parent(AppMessage::DataChanged {
                    source: self.name(),
                    row,
                    col,
                });
            }
        }
    }
}

## 5. diff 算法与 Patch 机制

### 5.1 概述

diff 算法比较新旧 `WidgetView<M>` 树，产生 `Patch` 列表。框架将 Patch 应用到 retained widget 树。

设计目标：
- **O(n)** 最坏时间复杂度（n = 节点数）
- **< 1ms** 处理 1000 节点树（V5 验证基准）
- **keyed reconciliation** 处理动态列表

### 5.2 Patch 类型

```rust
/// Widget 树补丁：描述从旧视图到新视图的变化。
#[derive(Debug, Clone)]
pub enum Patch<M: AppMessage> {
    /// 创建新 widget 节点。
    CreateWidget {
        /// 父节点 ID
        parent: WidgetId,
        /// 在父节点 children 中的插入位置
        index: usize,
        /// widget 类型名
        widget_type: &'static str,
        /// 新分配的 WidgetId
        widget_id: WidgetId,
        /// 初始属性
        props: BTreeMap<&'static str, PropValue>,
        /// 初始消息绑定
        message_bindings: Vec<MessageBinding<M>>,
    },

    /// 更新已有 widget 的属性。
    UpdateProps {
        widget_id: WidgetId,
        /// 新增或修改的属性
        changed: BTreeMap<&'static str, PropValue>,
        /// 移除的属性名
        removed: Vec<&'static str>,
    },

    /// 更新消息绑定。
    UpdateBindings {
        widget_id: WidgetId,
        bindings: Vec<MessageBinding<M>>,
    },

    /// 移动 widget 到新位置。
    MoveWidget {
        widget_id: WidgetId,
        new_parent: WidgetId,
        new_index: usize,
    },

    /// 移除 widget（及其子节点）。
    RemoveWidget {
        widget_id: WidgetId,
    },

    /// 替换 widget 类型（old_type ≠ new_type）。
    ReplaceWidget {
        /// 旧 widget ID（被替换）
        widget_id: WidgetId,
        /// 新的 widget 类型
        new_widget_type: &'static str,
        /// 新属性
        props: BTreeMap<&'static str, PropValue>,
        /// 新消息绑定
        message_bindings: Vec<MessageBinding<M>>,
    },

    /// 批量 patch（用于列表 reconciliation）。
    Batch(Vec<Patch<M>>),
}
```

### 5.3 diff 算法

```rust
/// 比较新旧 WidgetView 树，产生 Patch 列表。
///
/// # 算法流程
///
/// 1. 从根节点开始递归比较
/// 2. 对每个节点：
///    a. 比较 widget_type —— 不同则 ReplaceWidget
///    b. 比较 props —— 产生 UpdateProps（增/改/删）
///    c. 比较 message_bindings —— 产生 UpdateBindings
///    d. 比较 children —— 对子节点列表做 reconciliation
/// 3. 子节点 reconciliation：
///    a. 有 key 的节点：按 key 做集合比较（匹配、新增、删除、移动）
///    b. 无 key 的节点：按位置逐一比较
pub fn diff<M: AppMessage>(
    old_view: &WidgetView<M>,
    new_view: &WidgetView<M>,
    parent_id: WidgetId,
    id_map: &mut WidgetIdMap,
) -> Vec<Patch<M>> {
    let mut patches = Vec::new();
    diff_recursive(old_view, new_view, parent_id, 0, id_map, &mut patches);
    patches
}

fn diff_recursive<M: AppMessage>(
    old: &WidgetView<M>,
    new: &WidgetView<M>,
    parent_id: WidgetId,
    child_index: usize,
    id_map: &mut WidgetIdMap,
    patches: &mut Vec<Patch<M>>,
) {
    let widget_id = resolve_id(old, new, parent_id, child_index, id_map);
```

/// 解析节点身份：按优先级确定新旧 WidgetView 是否对应同一 widget。
///
/// 查找优先级：
/// 1. new.id 已设置 → 从 stable_id_to_id 查找
/// 2. old.id 已设置 → 从 stable_id_to_id 查找（节点移动场景）
/// 3. 按 parent_id + child_index 路径查找
/// 4. 均未命中 → 新节点，调用 id_map.allocate() 分配新 WidgetId
fn resolve_id<M: AppMessage>(
    old: &WidgetView<M>,
    new: &WidgetView<M>,
    parent_id: WidgetId,
    child_index: usize,
    id_map: &mut WidgetIdMap,
) -> WidgetId {
    if let Some(stable_id) = new.id.or(old.id) {
        if let Some(existing) = id_map.stable_id_to_id.get(&stable_id.name) {
            return *existing;
        }
    }
    if let Some(existing) = id_map.get_by_path(parent_id, child_index) {
        return existing;
    }
    id_map.allocate()
}

    // 1. 类型变更 → 完全替换
    if old.widget_type != new.widget_type {
        patches.push(Patch::ReplaceWidget {
            widget_id,
            new_widget_type: new.widget_type,
            props: new.props.clone(),
            message_bindings: new.message_bindings.clone(),
        });
        return;
    }

    // 2. 属性 diff
    let prop_patch = diff_props(&old.props, &new.props);
    if let Some(patch) = prop_patch {
        patches.push(Patch::UpdateProps {
            widget_id,
            changed: patch.changed,
            removed: patch.removed,
        });
    }

    // 3. 消息绑定 diff
    if old.message_bindings != new.message_bindings {
        patches.push(Patch::UpdateBindings {
            widget_id,
            bindings: new.message_bindings.clone(),
        });
    }

    // 4. 子节点 reconciliation
    let child_patches = reconcile_children(
        &old.children,
        &new.children,
        widget_id,
        id_map,
    );
    patches.extend(child_patches);
}
```

### 5.4 子节点 Reconciliation

```rust
/// 子节点 reconciliation。
///
/// 策略：
/// 1. 所有节点都有 key → 按 key 做集合 diff（O(n)）
/// 2. 部分有 key → 有 key 的按 key 匹配，无 key 的按位置匹配
/// 3. 都无 key → 按位置逐一比较
fn reconcile_children<M: AppMessage>(
    old_children: &[WidgetView<M>],
    new_children: &[WidgetView<M>],
    parent_id: WidgetId,
    id_map: &mut WidgetIdMap,
) -> Vec<Patch<M>> {
    let all_have_keys = new_children.iter().all(|c| c.key.is_some())
        && old_children.iter().all(|c| c.key.is_some());

    if all_have_keys {
        keyed_reconciliation(old_children, new_children, parent_id, id_map)
    } else {
        positional_reconciliation(old_children, new_children, parent_id, id_map)
    }
}

/// 基于 key 的 reconciliation（类 React）。
fn keyed_reconciliation<M: AppMessage>(
    old_children: &[WidgetView<M>],
    new_children: &[WidgetView<M>],
    parent_id: WidgetId,
    id_map: &mut WidgetIdMap,
) -> Vec<Patch<M>> {
    let mut patches = Vec::new();

    // 构建旧 key 索引
    let old_by_key: FxHashMap<&Key, (usize, WidgetId)> = old_children
        .iter()
        .enumerate()
        .filter_map(|(i, c)| {
            let key = c.key.as_ref()?;
            let id = id_map.get_by_path(parent_id, i)?;
            Some((key, (i, id)))
        })
        .collect();

    // 构建新 key 集合
    let new_keys: FxHashSet<&Key> = new_children
        .iter()
        .filter_map(|c| c.key.as_ref())
        .collect();

    // 删除：旧 key 不在新 key 中
    for (key, (_idx, id)) in &old_by_key {
        if !new_keys.contains(key) {
            patches.push(Patch::RemoveWidget { widget_id: *id });
        }
    }

    // 新增 + 更新
    for (new_idx, new_child) in new_children.iter().enumerate() {
        if let Some(key) = &new_child.key {
            if let Some(&(_old_idx, old_id)) = old_by_key.get(key) {
                diff_recursive(&old_children[_old_idx], new_child, parent_id, new_idx, id_map, &mut patches);
            } else {
                patches.push(Patch::CreateWidget {
                    parent: parent_id,
                    index: new_idx,
                    widget_type: new_child.widget_type,
                    widget_id: id_map.allocate(),
                    props: new_child.props.clone(),
                    message_bindings: new_child.message_bindings.clone(),
                });
            }
        }
    }

    patches
}

/// 基于位置的 reconciliation。
fn positional_reconciliation<M: AppMessage>(
    old_children: &[WidgetView<M>],
    new_children: &[WidgetView<M>],
    parent_id: WidgetId,
    id_map: &mut WidgetIdMap,
) -> Vec<Patch<M>> {
    let mut patches = Vec::new();
    let max_len = old_children.len().max(new_children.len());

    for i in 0..max_len {
        match (old_children.get(i), new_children.get(i)) {
            (Some(old), Some(new)) => {
                diff_recursive(old, new, parent_id, i, id_map, &mut patches);
            }
            (None, Some(new)) => {
                patches.push(Patch::CreateWidget {
                    parent: parent_id,
                    index: i,
                    widget_type: new.widget_type,
                    widget_id: id_map.allocate(),
                    props: new.props.clone(),
                    message_bindings: new.message_bindings.clone(),
                });
            }
            (Some(old), None) => {
                if let Some(id) = id_map.get_by_path(parent_id, i) {
                    patches.push(Patch::RemoveWidget { widget_id: id });
                }
            }
            (None, None) => unreachable!(),
        }
    }

    patches
}

/// 属性 diff 结果。
struct PropDiff {
    changed: BTreeMap<&'static str, PropValue>,
    removed: Vec<&'static str>,
}

/// 比较两个属性映射。
fn diff_props(
    old: &BTreeMap<&'static str, PropValue>,
    new: &BTreeMap<&'static str, PropValue>,
) -> Option<PropDiff> {
    let mut changed = BTreeMap::new();
    let mut removed = Vec::new();

    for (key, new_val) in new {
        match old.get(key) {
            Some(old_val) if old_val == new_val => {}
            _ => { changed.insert(*key, new_val.clone()); }
        }
    }

    for key in old.keys() {
        if !new.contains_key(key) {
            removed.push(*key);
        }
    }

    if changed.is_empty() && removed.is_empty() {
        None
    } else {
        Some(PropDiff { changed, removed })
    }
}

### 5.5 WidgetId 查找表

WidgetIdMap 是 diff 过程中的局部 ID 映射表，将路径（`parent_id + index`）和稳定 ID 映射到 StateStore 分配的全局 WidgetId。其 `allocate()` 方法委托 StateStore 的全局分配器分配新 WidgetId（非独立 ID 空间）。diff 完成后，StateStore 是 WidgetId 的唯一来源。

```rust
#[derive(Debug, Default)]
pub struct WidgetIdMap {
    path_to_id: FxHashMap<WidgetPath, WidgetId>,
    stable_id_to_id: FxHashMap<&'static str, WidgetId>,
    next_id: u64,
}

#[derive(Debug, Clone, PartialEq, Eq, Hash)]
struct WidgetPath {
    parent: WidgetId,
    index: usize,
}

impl WidgetIdMap {
    pub fn new() -> Self {
        WidgetIdMap {
            path_to_id: FxHashMap::default(),
            stable_id_to_id: FxHashMap::default(),
            next_id: 0,
        }
    }

    pub fn get_by_path(&self, parent: WidgetId, index: usize) -> Option<WidgetId> {
        self.path_to_id.get(&WidgetPath { parent, index }).copied()
    }

    pub fn allocate(&mut self) -> WidgetId {
        self.next_id += 1;
        WidgetId(NonZeroU64::new(self.next_id).expect("WidgetId 溢出"))
    }
}

## 6. 订阅模型

### 6.1 自动订阅建立

当 widget A 在 `update()` 中通过 `StoreAccessMut::read(target_id)` 读取 widget B 的状态时，框架自动建立订阅。

```
订阅建立流程：

1. Widget A 调用 store.read::<B::State>(widget_b_id)
2. StoreAccessMut::read() 记录订阅：
   new_subscriptions.push((widget_b_id, Subscription {
       subscriber: widget_a_id,
       lifetime: Persistent
   }))
3. update() 返回后，框架将订阅写入 StateStore.subscriptions
4. 当 Widget B 的状态变更时：
   a. mark_dirty(widget_b_id)
   b. propagate_dirty(widget_b_id)
      → subscriptions[widget_b_id]
      → 标记 widget_a_id dirty
      → 递归传播
```

### 6.2 订阅生命周期管理

```rust
impl StateStore {
    /// 在处理 update() 之后，应用新的订阅关系。
    pub(crate) fn apply_subscriptions(
        &mut self,
        self_id: WidgetId,
        new_subs: Vec<(WidgetId, Subscription)>,
    ) {
        // 清除 self_id 的旧订阅
        for subs in self.subscriptions.values_mut() {
            subs.retain(|s| s.subscriber != self_id);
        }
        // 添加新订阅
        for (target_id, sub) in new_subs {
            self.subscriptions.entry(target_id).or_default().push(sub);
        }
    }

    /// 清理无效订阅（被订阅的 widget 已卸载）。
    pub(crate) fn cleanup_subscriptions(&mut self) {
        self.subscriptions.retain(|target_id, _| {
            self.persistent.contains_key(target_id)
        });
        for subs in self.subscriptions.values_mut() {
            subs.retain(|s| self.persistent.contains_key(&s.subscriber));
        }
    }
}
```

### 6.3 循环依赖检测

```rust
impl StateStore {
    /// 检测订阅图中是否存在循环。
    ///
    /// 使用 DFS + in_stack 标记检测。若检测到循环，记录警告并返回循环中的 widget ID 列表。
    pub fn detect_cycles(&self) -> Vec<Vec<WidgetId>> {
        let mut cycles = Vec::new();
        let mut visited = FxHashSet::default();
        let mut in_stack = FxHashSet::default();

        for &widget_id in self.subscriptions.keys() {
            if !visited.contains(&widget_id) {
                let mut path = Vec::new();
                self.dfs_detect_cycle(widget_id, &mut visited, &mut in_stack, &mut path, &mut cycles);
            }
        }

        cycles
    }

    fn dfs_detect_cycle(
        &self,
        current: WidgetId,
        visited: &mut FxHashSet<WidgetId>,
        in_stack: &mut FxHashSet<WidgetId>,
        path: &mut Vec<WidgetId>,
        cycles: &mut Vec<Vec<WidgetId>>,
    ) {
        visited.insert(current);
        in_stack.insert(current);
        path.push(current);

        if let Some(subs) = self.subscriptions.get(&current) {
            for sub in subs {
                if in_stack.contains(&sub.subscriber) {
                    let cycle_start = path.iter()
                        .position(|&id| id == sub.subscriber)
                        .unwrap_or(0);
                    cycles.push(path[cycle_start..].to_vec());
                } else if !visited.contains(&sub.subscriber) {
                    self.dfs_detect_cycle(sub.subscriber, visited, in_stack, path, cycles);
                }
            }
        }

        path.pop();
        in_stack.remove(&current);
    }
}

### 7.2 Snapshotter

```rust
/// 快照管理器。
pub struct Snapshotter {
    /// 所有快照，按序号索引
    snapshots: Vec<Snapshot>,

    /// 最大快照数量（超出后 FIFO 淘汰）
    max_snapshots: usize,

    /// 当前序号
    next_sequence: u64,
}

impl Snapshotter {
    /// 创建 Snapshotter。
    pub fn new(max_snapshots: usize) -> Self {
        Snapshotter {
            snapshots: Vec::with_capacity(max_snapshots),
            max_snapshots,
            next_sequence: 0,
        }
    }

    /// 从 StateStore 创建快照。
    pub fn capture(
        &mut self,
        state_store: &StateStore,
        framework_version: &str,
    ) -> Snapshot {
        let mut states = HashMap::new();

        for (&id, boxed_state) in &state_store.persistent {
            let mut buffer = Vec::new();
            let mut serializer = postcard::Serializer::new(&mut buffer);
            boxed_state
                .erased_serialize(&mut serializer)
                .expect("PersistState 序列化不应失败");

            states.insert(id.0, SerializedState {
                schema_name: boxed_state.schema_name().to_string(),
                schema_version: boxed_state.schema_version(),
                data: buffer,
            });
        }

        let snapshot = Snapshot {
            framework_version: framework_version.to_string(),
            timestamp_ms: now_millis(), // 内部辅助函数：SystemTime::now().duration_since(UNIX_EPOCH).as_millis()
            sequence: self.next_sequence,
            states,
        };

        self.next_sequence += 1;

        if self.snapshots.len() >= self.max_snapshots {
            self.snapshots.remove(0);
        }
        self.snapshots.push(snapshot.clone());

        snapshot
    }

    /// 按序号获取快照。
    pub fn get(&self, sequence: u64) -> Option<&Snapshot> {
        self.snapshots.iter().find(|s| s.sequence == sequence)
    }

    /// 返回所有快照的序号列表。
    pub fn sequences(&self) -> Vec<u64> {
        self.snapshots.iter().map(|s| s.sequence).collect()
    }
}

### 7.3 Schema 迁移

```rust
/// Schema 迁移注册表。
pub struct SchemaMigrationRegistry {
    /// schema_name → 迁移列表（按 version 排序）
    migrations: FxHashMap<String, Vec<Box<dyn SchemaMigration>>>,
}

/// 单个迁移：从 version_from 到 version_to。
pub trait SchemaMigration: Send + Sync {
    fn schema_name(&self) -> &str;
    fn from_version(&self) -> u32;
    fn to_version(&self) -> u32;
    fn migrate(&self, data: &[u8]) -> Result<Vec<u8>, MigrationError>;
}

/// 迁移错误。
#[derive(Debug, thiserror::Error)]
pub enum MigrationError {
    #[error("找不到从版本 {from} 到 {to} 的迁移路径（schema: {schema}）")]
    NoPath { schema: String, from: u32, to: u32 },

    #[error("迁移执行失败：{0}")]
    ExecutionFailed(String),
}

impl SchemaMigrationRegistry {
    pub fn new() -> Self {
        SchemaMigrationRegistry {
            migrations: FxHashMap::default(),
        }
    }

    pub fn register<M: SchemaMigration + 'static>(&mut self, migration: M) {
        self.migrations
            .entry(migration.schema_name().to_string())
            .or_default()
            .push(Box::new(migration));
    }

    pub fn current_version(&self, schema_name: &str) -> u32 {
        self.migrations
            .get(schema_name)
            .and_then(|ms| ms.iter().map(|m| m.to_version()).max())
            .unwrap_or(1)
    }

    pub fn migrate(
        &self,
        schema_name: &str,
        from_version: u32,
        data: &[u8],
    ) -> Result<Vec<u8>, MigrationError> {
        let migrations = self.migrations.get(schema_name).ok_or_else(|| {
            MigrationError::NoPath {
                schema: schema_name.to_string(),
                from: from_version,
                to: self.current_version(schema_name),
            }
        })?;

        let mut current_version = from_version;
        let mut current_data = data.to_vec();

        while current_version < self.current_version(schema_name) {
            let next = migrations
                .iter()
                .find(|m| m.from_version() == current_version)
                .ok_or_else(|| MigrationError::NoPath {
                    schema: schema_name.to_string(),
                    from: current_version,
                    to: self.current_version(schema_name),
                })?;

            current_data = next.migrate(&current_data)?;
            current_version = next.to_version();
        }

        Ok(current_data)
    }
}

### 8.1 快速重启流程

```
1. 用户修改 .rs 文件，保存
2. cargo build 增量编译（~2-5s）
3. 框架捕获当前快照

5. 新进程接收快照

7. 所有 widget 重新执行 view()（基于恢复的状态）→ diff → patch

```

## 10. 边界情况处理

### 10.1 空状态

- `StateStore` 初始为空，所有字段为空集合
- 快照包含 0 个状态：合法，恢复为空 StateStore

### 10.2 状态类型不匹配

- 检测：通过 `downcast_ref` 检测类型 ID
- 处理：panic（框架内部不一致，不应在生产中出现）

### 10.3 快照中 widget 类型已删除

- 快照包含旧版本定义的 widget，当前版本已删除该类型
- 处理：恢复时跳过未知 widget 的状态，记录警告日志

### 10.4 超大快照

- 状态数据总量 > 100MB
- 策略：压缩（zstd）、分块传输（≤ 16MB）、对超大状态标记为「延迟恢复」

### 10.5 脏标记传播风暴

- 一个状态变更触发大量订阅者同时 dirty
- 缓解：dirty 传播是 BFS，单 widget 在一帧内只标记一次

### 10.6 订阅泄漏

- widget 卸载时订阅关系残留
- `cleanup_subscriptions()` 每 60 帧执行一次；`remove()` 方法主动清理

## 11. 性能设计

### 11.1 关键路径

| 操作 | 目标延迟 | 数据结构 |
|------|---------|---------|
| 状态读取 | < 10ns | FxHashMap（u64 键） |
| 状态写入 + dirty 标记 | < 50ns | FxHashMap + FxHashSet |
| WidgetView diff（1000 节点） | < 1ms | 递归 DFS，O(n) |
| 属性 diff（100 props） | < 10µs | BTreeMap 双向扫描 |
| 快照序列化（100 widgets） | < 50ms | postcard |
| 循环依赖检测 | 非热路径 | DFS，按需执行 |

### 11.2 内存预算

| 数据 | 单 widget 估计 | 1000 widget 估计 |
|------|--------------|-----------------|
| 持久状态 | 100B-10KB | 100KB-10MB |
| 实例态 | ~200B | ~200KB |
| 缓存态 | ~2KB | ~2MB |
| 订阅关系 | ~40B/sub | ~100KB |
| 总计（典型应用） | — | ~3-15MB |

### 11.3 优化策略

1. **增量 diff**：仅 dirty widget 子树参与 diff
2. **属性 diff 短路**：`BTreeMap::len()` 快速判断是否需要迭代
3. **postcard 序列化**：零拷贝反序列化，比 serde_json 快约 10×
4. **FxHash**：整数键哈希性能优于标准 HashMap
5. **layout 缓存**：Taffy 布局结果不重算（除非 constraints 变化）
