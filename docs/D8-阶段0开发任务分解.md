## 1. 任务分解方法

- 每项任务 ≤ 3 个工作日，有明确验收标准
- 优先级：P0（阻塞）> P1（核心）> P2（增强）> P3（优化）
- 人力假设：1 全职 + 1 兼职贡献者

## 9. 设计文档审计补充任务

> **来源：** 2026-06-17 对 D0-D7 设计文档的系统审计，提取 D8 原始任务清单中遗漏的实现项。部分项直接并入现有任务（修改验收标准），部分新增独立任务。
>
> **审计重点：**（1）DPI/scale_factor 端到端处理（渲染管线实际运行在物理像素空间，scale_factor 基础设施存在但从未接线）；（2）各文档中定义但 D8 未列入的类型/trait/方法；（3）跨子系统不变式验证。

### 9.1 跨子系统任务

| # | 任务 | 优 | 验收标准 |
|---|------|----|---------|
| CC01 | **DPI/scale_factor 端到端接线** — 当前全链路运行在物理像素空间（winit 返回 PhysicalSize → self.width/height → RenderParams → SceneGraph 坐标 → wgpu surface），scale_factor 字段存在但永远为 1.0。需要：① `app.rs` 在构造 RenderParams 前调用 `window.scale_factor()`；② 场景构建层在编码时用 scale_factor 对逻辑坐标做变换，或将管线统一为逻辑像素+后端缩放；③ 组件 paint()/measure() 中的 font_size 使用逻辑像素 | P0 | 窗口从 1× 屏拖到 2× 屏，widget 视觉大小不变；`window.scale_factor()` 返回值被 RenderParams 消费 |
| CC02 | **坐标系契约明确化** — 在 `rgui-core::geometry` 模块文档中明确：Point/Size/Rect 为逻辑像素（设备无关），物理像素仅在 RenderBackend trait 边界出现。命中测试坐标（winit CursorMoved.PhysicalPosition）需在 `convert_winit_event()` 中除以 scale_factor 转为逻辑 | P0 | geometry.rs 模块文档含坐标系统说明；hit test 使用逻辑坐标 |

### 9.13 四次审计补充任务（CJK 文字渲染实验发现）

> **来源：** 2026-06-18 CheckBox 组件中文标签渲染实验。当前仅嵌入 Inter（拉丁字体），中文等 CJK 字符通过 `load_system_fonts()` 由 cosmic-text 塑形使用系统字体（macOS PingFang SC），但 Vello 渲染时 `draw_glyphs()` 使用的 `FontData` 硬编码为 Inter，导致 glyph ID 与塑形字体不匹配（显示为 `.notdef` ① 或空白）。

> **根因：** Vello 0.9 `draw_glyphs()` API 仅支持单字体 `FontData`，无法支持多字体混合渲染。完整方案需（1）Vello 升级至支持 atlas-based 字形纹理渲染；或（2）实现 per-glyph 字体路由，将塑形时使用的字体数据传递到渲染端。两者均需跨 `rgui-render` + `rgui-core` 的架构变更，超出阶段 0 范围。

| # | 任务 | 优 | 验收标准 |
|---|------|----|---------|
| M15 | **CJK/多语言文字渲染支持** — 支持中、日、韩等非拉丁文字渲染。需解决 Vello `draw_glyphs` 单字体限制：通过多字体 FontData 路由或 atlas-based 字形纹理渲染，使塑形字体与渲染字体一致 | P2 | 中文等 CJK 文字在 CheckBox/Label 等组件中正确渲染为实际字形 |
