## 1. 设计目标与范围

### 1.1 本文档解决什么问题

1. 定义从 winit 原始事件到框架事件的类型体系
2. 定义事件在 widget 树中的路由机制（显式事件连接——Signal/Slot 风格，目标阶段直达）
3. 定义命中测试算法（确定哪个 widget 响应坐标点击）
4. 定义焦点管理（Tab 导航、焦点链、焦点恢复）
5. 定义 IME 集成接口（组合文本、候选窗口位置）

### 1.2 设计原则

1. **事件是不可变值类型**：事件在传递链中为只读
2. **命中测试基于布局结果**：使用 Taffy 产出的 widget 边界矩形
3. **焦点遵循 WCAG**：Tab 序遵循视觉顺序，支持焦点陷阱（模态对话框）

## 2. 事件类型体系

### 2.1 框架事件枚举

```rust
/// 鼠标输入来源（保留原始窗口坐标证据，便于调试和回归验证）。
#[derive(Debug, Clone, Copy, PartialEq)]
pub enum MouseInputOrigin {
    PlatformWindowEvent {
        raw_window_position: Point,
        normalization: CoordinateNormalization,
    },
    PhysicalInjection {
        raw_window_position: Point,
        normalization: CoordinateNormalization,
    },
    LogicalInjection,
}

/// 鼠标事件坐标集合。
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct MouseEventCoords {
    pub window_logical: Point,
    pub local_logical: Option<Point>,
    pub origin: MouseInputOrigin,
}

/// 框架统一事件类型（从平台原始窗口事件转换）。
#[derive(Debug, Clone)]
pub enum Event {
    MouseDown {
        coords: MouseEventCoords,
        button: MouseButton,
        modifiers: Modifiers,
    },
    MouseUp {
        coords: MouseEventCoords,
        button: MouseButton,
        modifiers: Modifiers,
    },
    MouseMove {
        coords: MouseEventCoords,
        delta_window_logical: Point,
        modifiers: Modifiers,
    },
    MouseWheel {
        coords: MouseEventCoords,
        delta_x: f64,
        delta_y: f64,
        modifiers: Modifiers,
    },
    MouseEnter { widget_id: WidgetId },
    MouseLeave { widget_id: WidgetId },

    KeyDown { key: Key, modifiers: Modifiers, repeat: bool },
    KeyUp { key: Key, modifiers: Modifiers },

    ImePreedit { text: String, cursor_offset: usize },
    ImeCommit { text: String },
    ImeEnabled,
    ImeDisabled,

    FocusIn { widget_id: WidgetId, source: FocusSource },
    FocusOut { widget_id: WidgetId },

    DragEnter { coords: MouseEventCoords },
    DragOver { coords: MouseEventCoords },
    DragLeave,
    Drop { coords: MouseEventCoords },

    WindowResized { width: f64, height: f64 },
    WindowFocused,
    WindowUnfocused,
    ScaleFactorChanged { scale_factor: f64 },
    ThemeChanged { color_scheme: ColorScheme },
    CloseRequested,
}
```

鼠标与拖拽事件中的 `coords.window_logical` 与 `coords.local_logical` 采用 Qt 一致性语义：前者是高层统一窗口逻辑坐标，后者是命中接收者后的局部坐标；`coords.origin` 保留平台原始窗口输入或自动化注入证据。详细约束见 D14。

### 2.3 事件流

```
平台窗口事件 / 自动化回放
  → normalize_platform_window_point() 归一化为窗口逻辑坐标
  → 组装 MouseEventCoords / Event
  → 命中测试（确定 target WidgetId）
  → 目标 widget handler 调用（register_widget_instance 注册的处理器）
  → [可选] Rhai 命令处理器路由（command_registry.call_fn）
  → [可选] 旧 register_interaction 回调（fallback）
```

事件不沿 widget 树传播——走 **Qt Signal/Slot 显式连接模型**：
- 点击事件直接路由到命中测试确定的目标 widget（`handle_click` → `handler(action, ctx)`）
- 组件间通信通过 `widget_state_store` 显式读写（见 §3.4）
- 需要"父组件响应子组件事件"时，由子组件 handler 显式写入父组件的 state store key，父组件 paint() 读取

## 3. 事件路由（显式连接）

> **设计变更（2026-06-22）：** 原 DOM 风格 EventRouter（捕获→目标→冒泡三阶段路由）已废弃。
> rgui 采用 **Qt Signal/Slot 风格的显式连接模型**。事件直接发送到命中测试确定的目标 widget，
> 组件间通信通过 `widget_state_store` 显式读写完成。

### 3.1 路由架构

点击事件路由在 `App::handle_click()` 中完成（见 `rgui/src/app.rs`）：

```
MouseDown 事件
  → handle_click(coords.window_logical)
  → find_widget_at_point(coords.window_logical) → hit_id: WidgetId
  → widget_instances[hit_id](action, ctx) → EventResult
     ├─ Handled   → 停止（组件消费事件）
     ├─ Prevented → 阻止旧回调 fallback，request_redraw
     └─ Continue  → 继续到 Rhai 路由 → 旧 register_interaction 回调
```

关键结构：

```rust
/// Widget 实例处理器类型（= Qt slot）。
type WidgetUpdateHandler = Box<dyn FnMut(&str, &mut UpdateContext) -> EventResult<String> + Send>;
```

```rust
/// App 中的事件路由相关字段（rgui/src/app.rs）
pub struct App {
    /// Widget 实例处理器注册表（= Qt 连接表）
    widget_instances: FxHashMap<WidgetId, WidgetUpdateHandler>,
    /// 组件实例状态存储（= Qt 跨对象通信）
    widget_state_store: WidgetStateStore,
    /// 待处理事件队列（每帧 tick() 结束时 drain）
    events: Vec<Event>,
    /// 当前 WidgetView 树（用于 DFS 命中测试）
    current_view: Arc<Mutex<Option<WidgetView<NoopMsg>>>>,
    /// 最新布局引擎（用于绝对坐标计算）
    current_layout: Arc<Mutex<Option<LayoutEngine>>>,
    // ...
}
```

### 3.2 处理器注册（`register_widget_instance` = Qt `connect`）

```rust
impl App {
    /// 注册 widget 实例的点击处理器。
    ///
    /// 等价于 Qt 的 `connect(widget, SIGNAL(clicked()), receiver, SLOT(handler()))`。
    ///
    /// - `id`: widget ID（需与 html! 中 id="..." 对应）
    /// - `handler`: 事件处理器，接收动作名称，返回 EventResult
    ///
    /// 当 handle_click 命中此 widget 时，直接调用 handler。
    /// 根据返回的 EventResult 决定是否继续到旧 register_interaction 回调。
    pub fn register_widget_instance(
        &mut self,
        id: WidgetId,
        handler: impl FnMut(&str, &mut UpdateContext) -> EventResult<String> + Send + 'static,
    ) {
        self.widget_instances.insert(id, Box::new(handler));
    }
}
```

**路由优先序**（从高到低）：
1. **WidgetSpec 实例处理器**（`widget_instances[hit_id]`）——组件内部 update()
2. **Rhai 命令处理器**（`command_registry.call_fn(action)`）——`.rhai` 脚本函数
3. **旧 register_interaction 回调**（`interactions[hit_id]`）——向后兼容 fallback

### 3.3 EventResult 消费控制

```rust
pub enum EventResult<M> {
    /// 事件已完全处理，停止后续路由。
    Handled,
    /// 阻止默认行为（旧 register_interaction 回调不执行），但标记需要重绘。
    Prevented,
    /// 继续传播到下一优先级处理器，携带动作名称。
    Continue(M),
}
```

- `Handled`：组件消费事件 → `request_redraw()` + 停止全部路由
- `Prevented`：阻止默认行为 → `request_redraw()` + 跳过旧回调 fallback
- `Continue`：继续到 Rhai 路由和旧回调路径

### 3.4 组件间通信（`widget_state_store` = Qt 跨对象调用）

组件间通信不通过事件冒泡，而是通过 `WidgetStateStore` 显式读写：

```rust
/// 组件实例状态存储（跨帧持久化）。
///
/// .rgui 渲染路径中，paint_factory 每帧从 WidgetView.props 创建临时 state。
/// widget_state_store 使交互组件能在此持久化自己的状态，
/// paint_factory 读取 + widget_instance handler 写入，实现组件行为自包含。
pub struct WidgetStateStore {
    states: Arc<Mutex<HashMap<String, PropValue>>>,
}

impl WidgetStateStore {
    pub fn get(&self, key: &str) -> Option<PropValue> { /* ... */ }
    pub fn set(&self, key: &str, value: PropValue) { /* ... */ }
    pub fn remove(&self, key: &str) { /* ... */ }
}
```

**使用模式：**
- **写入**（在 handler 中）：`ctx.widget_state_store.set("accordion_1.open", PropValue::Bool(true))`
- **读取**（在 paint 中）：`state_store.get("accordion_1.open")` → 决定展开/折叠绘制
- **跨组件通信**：子组件 handler 写入 `"parent_section.active_tab"`，父组件 paint 读取

这等价于 Qt 中 slot 调用其他对象方法——区别是 rgui 通过共享状态存储而非直接方法调用。

### 3.5 事件队列

```rust
/// App 中的事件队列字段
events: Vec<Event>,
```

- 每帧 `tick()` 开始时，winit 事件被转换并推入 `events`
- handler 执行过程中可通过 `ctx.push_event()` 追加事件
- 每帧 `tick()` 结束时 `drain` 队列——所有事件在下一帧分发
- 队列无容量上限，由调用方保证不高频堆积
- 滚动等高频场景需配合 throttle（≤ 1 次/帧）

> **废弃说明：** 原 `EventSender.consumed` 和 `EventSender.default_prevented` 字段在显式连接模型中不再需要。
> 事件消费由 `EventResult` 枚举控制（见 §3.3）；`EventSender` 保留仅作队列容器。
> P04d 将删除 handle_click 中剩余的捕获/冒泡循环代码。

### 3.6 与 DOM 事件模型的差异

| 特性 | DOM（已废弃） | rgui（Qt Signal/Slot） |
|------|-------------|----------------------|
| 事件传播 | 捕获 → 目标 → 冒泡三阶段 | 直接目标 widget handler |
| 事件消费 | `stopPropagation()` / `preventDefault()` | `EventResult::Handled` / `Prevented` |
| 父子通信 | 冒泡到父元素 | `widget_state_store` 显式读写 |
| 处理器注册 | `addEventListener` | `register_widget_instance` |
| 跨组件通信 | 冒泡 + 事件委托 | `widget_state_store.set(key, value)` |

## 4. 命中测试

```rust
impl WidgetTree {
    /// 命中测试：返回坐标处最深的 widget ID。
    ///
    /// 算法：
    /// 1. 从根节点开始
    /// 2. 检查当前节点包含坐标
    /// 3. 子节点按 z-index 降序排列后递归检查（高 z-index 优先命中，
    ///    无 z-index 时按 child 索引递增作为默认值，与 SceneGraph 的
    ///    z-order 排序一致）
    /// 4. 返回最深匹配
    pub fn hit_test(&self, point: Point) -> Option<WidgetId> {
        self.hit_test_recursive(self.root(), point)
    }

    fn hit_test_recursive(&self, widget_id: WidgetId, point: Point) -> Option<WidgetId> {
        let bounds = self.bounds.get(&widget_id)?;
        if !bounds.contains(point) { return None; }

        if let Some(children) = self.children.get(&widget_id) {
            // 按 z-index 降序排列子节点（z-order 与 SceneGraph 一致）
            let mut sorted: Vec<_> = children.iter().copied().collect();
            sorted.sort_by_key(|&id| {
                // 从 widget props 读取 z-index，无则用 0（与 scene_build 一致）
                self.z_index(id).unwrap_or(0)
            });
            for child in sorted.into_iter().rev() {
                if let Some(hit) = self.hit_test_recursive(child, point) {
                    return Some(hit);
                }
            }
        }
        Some(widget_id)
    }

    fn z_index(&self, _widget_id: WidgetId) -> Option<i32> { /* 从 props 或 SceneGraph 读取 */ None }

    pub fn root(&self) -> WidgetId { /* 返回 widget 树的根节点 ID */ todo!() }

    pub fn traverse_visual_order(&self) -> Vec<WidgetId> { /* DFS 遍历产生视觉序列表 */ todo!() }
}
```

**性能优化**：缓存最近命中测试结果（鼠标连续移动）；> 500 节点时使用 R-tree 空间索引；虚拟滚动容器只检查可见子节点。

```rust
            .into_iter()
            .filter(|&id| self.is_focusable(id))
            .collect();
    }
```

```rust
/// 两个矩形之间的最短距离。

    pub fn find_nearest(
        current: Rect, direction: Direction,
        candidates: &[(WidgetId, Rect)],
    ) -> Option<WidgetId> {
        candidates.iter()
            .filter(|(_, rect)| is_in_direction(current, *rect, direction))
            .min_by_key(|(_, rect)| distance(current, *rect))
```

## 7. IME 集成

```rust
/// IME 管理器。
pub struct ImeManager {
    enabled: bool,
    preedit_text: String,
    preedit_cursor: usize,
    candidate_position: Point,
}

impl ImeManager {
    pub fn enable(&mut self, cursor_position: Point) {
        self.enabled = true;
        self.candidate_position = cursor_position;
    }

    pub fn disable(&mut self) {
        self.enabled = false;
        self.preedit_text.clear();
    }

    pub fn handle_preedit(&mut self, text: String, cursor_offset: usize) -> String {
        self.preedit_text = text.clone();
        self.preedit_cursor = cursor_offset;
        text
    }

    pub fn handle_commit(&mut self, text: String) -> String {
        let committed = text.clone();
        self.preedit_text.clear();
        self.preedit_cursor = 0;
        committed
    }
}
```

## 8. 剪贴板与拖放

```rust
/// 拖放数据。
#[derive(Debug, Clone)]
pub enum DragData {
    Text(String),
    Files(Vec<PathBuf>),
    Image { width: u32, height: u32, data: Vec<u8> },
}
```

剪贴板通过 `arboard` crate（跨平台剪贴板）提供 `get_text()`/`set_text()` 接口。

拖放数据通过 `DragData` 结构体传递，支持文本、文件和图片格式。拖放事件按标准 Event 枚举（DragEnter/DragOver/DragLeave/Drop）通过事件路由分发，其中 `DragEnter`、`DragOver`、`Drop` 与 `MouseMove` / `MouseDown` / `MouseUp` 一样统一使用 `coords: MouseEventCoords` 表达窗口逻辑坐标、接收者局部坐标和原始输入来源。

调试输出必须显式标注坐标参考系，推荐直接打印结构化字段而不是复用旧 `position` 名称，例如：


## 9. 平台事件映射

```rust
/// 将平台窗口事件转换为框架 Event。
pub fn convert_winit_event(
    event: winit::event::WindowEvent,
    mouse_coords: MouseEventCoords,
) -> Option<Event> {
    match event {
        winit::event::WindowEvent::MouseInput { state, button, .. } => {
            let btn = convert_button(button);
            let modifiers = Modifiers::current();
            match state {
                winit::event::ElementState::Pressed => {
                    Some(Event::MouseDown { coords: mouse_coords, button: btn, modifiers })
                }
                winit::event::ElementState::Released => {
                    Some(Event::MouseUp { coords: mouse_coords, button: btn, modifiers })
                }
            }
        }
        winit::event::WindowEvent::CursorMoved { .. } => {
            Some(Event::MouseMove {
                coords: mouse_coords,
                delta_window_logical: Point { x: 0.0, y: 0.0 },
                modifiers: Modifiers::current(),
            })
        }
        winit::event::WindowEvent::KeyboardInput { event, .. } => {
            let key = convert_key(event.physical_key);
            match event.state {
                winit::event::ElementState::Pressed => Some(Event::KeyDown {
                    key, modifiers: Modifiers::current(), repeat: event.repeat,
                }),
                winit::event::ElementState::Released => Some(Event::KeyUp {
                    key, modifiers: Modifiers::current(),
                }),
            }
        }
        winit::event::WindowEvent::Ime(ime) => convert_ime(ime),
        winit::event::WindowEvent::MouseWheel { delta, .. } => {
            Some(Event::MouseWheel {
                coords: mouse_coords,
                delta_x: convert_scroll_delta(delta).x,
                delta_y: convert_scroll_delta(delta).y,
                modifiers: Modifiers::current(),
            })
        }
        winit::event::WindowEvent::Resized(size) => {
            let logical_size = logical_window_size_from_physical_size(
                size.width,
                size.height,
                current_scale_factor(),
            );
            Some(Event::WindowResized {
                width: logical_size.width,
                height: logical_size.height,
            })
        }
        winit::event::WindowEvent::Focused(focused) => {
            if focused { Some(Event::WindowFocused) } else { Some(Event::WindowUnfocused) }
        }
        winit::event::WindowEvent::CloseRequested => Some(Event::CloseRequested),
        _ => None,
    }
}
```

该示例刻意避免旧 `position` / `delta` 命名，并假定 `mouse_coords` 已在平台边界通过 `normalize_platform_window_point()` 与命中测试链路补齐 `coords.window_logical`、`coords.local_logical`、`coords.origin`。拖拽事件的转换规则相同：统一复用 `coords`，禁止额外引入单一 `position` 字段。

## 10. 边界情况处理

### 10.1 事件队列

`App.events: Vec<Event>` 持有待处理的框架事件。handler 执行过程中可通过
`ctx.push_event()` 向队列追加事件（如 `request_redraw()` 推送 `MouseDown` 事件）。
队列在每帧 tick() 结束时 drain，所有事件在下一帧分发。

- 队列无容量上限——由调用方保证不高频堆积
- 滚动等高频场景需配合 throttle（≤ 1 次/帧）

### 10.2 其他边界情况

| 情况 | 处理 |
|------|------|
| 鼠标在 widget 边界上 | 包含上/左边界，不含右/下边界（CSS 一致） |
| 组合键冲突 | 框架快捷键仅当窗口获得焦点时生效 |
| 焦点 widget 被移除 | 清除焦点，尝试聚焦最近兄弟节点 |
| IME 在非文本 widget | 禁用 IME，忽略 IME 事件 |
| 多点触控 | 主触控点走鼠标事件路径，其他走 Gesture 事件（阶段 2） |
