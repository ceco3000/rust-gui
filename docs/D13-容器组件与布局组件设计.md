> **状态：** 初版。

## 1. 问题：为什么容器组件是第一优先级

### 1.1 当前状态

rgui-components 已有 WaButton（从 Web Awesome button 翻译），框架具备基本的 paint/measure/事件处理 能力。但存在一个致命缺陷：

**没有任何容器组件。** 所有示例（counter、crud）都用 `Rect::new(x, y, w, h)` 手工绝对坐标摆放元素——相当于用 `position: absolute; left: Xpx; top: Ypx` 写整个页面。

### 1.2 后果

- 无法使用 flexbox 自动布局——改变窗口大小时所有元素位置错乱
- 无法构建真实 App 的典型布局（顶部导航 + 侧边栏 + 内容区）
- 即使翻译更多 WA 叶子组件（badge、spinner、checkbox），也只能绝对坐标摆放，没有实用价值

### 1.3 容器组件解决什么

完成 Container 及其语法糖后，开发者可以用声明式 HTML 编写布局：

```html
<Column gap="8" padding="16">
  <Row gap="4">
    <WaButton label="Cancel" />
    <WaButton label="OK" variant="primary" />
  </Row>
  <Divider />
  <Card>
    <WaButton label="Card Button" />
  </Card>
</Column>
```

不再需要一行 `Rect::new()`。

## 2. 设计原则

### 2.1 容器组件的共性

1. **不自己绘制内容**（Card 的装饰背景和 Divider 的线条除外）
2. **通过 CSS 属性控制布局**：`.rgui` 声明中设置 CSS 属性（`display`、`flex-direction`、`gap`、`padding` 等），框架通过 `rgui-layout` 映射到 Taffy `Style`
3. **子节点由 `WidgetView.children` 承载**：不需要特殊数据结构
4. **第 0 层无运行时状态**：纯布局组件没有 State，布局行为由 CSS 属性声明决定；第 1 层（Card/Divider）有装饰相关状态

### 2.2 容器组件 vs 叶子组件

| 维度 | 叶子组件（WaButton 等） | 容器组件（Container、Row 等） |
|------|--------------------------|---------------------------|
| children | 通常为空 | 有子 widget |
| 绘制 | 绘制自身内容（矩形、文本、图标） | 不绘制或仅绘制装饰（背景、边框） |
| 尺寸计算 | 根据内容大小计算（如文本宽度） | 由 Taffy 根据子节点大小和约束计算 |
| CSS 属性侧重 | 视觉属性（color、background、border） | 布局属性（display、flex-direction、gap） |
| 来源 | WA 翻译 | 自研（纯布局）+ WA 翻译（Card/Divider） |

> **注意：** "仅绘制装饰"仅限第 1 层组件（Card、Divider），第 0 层纯布局组件不产生任何绘制操作（见 §4.0）。

## 3. 自研 vs WA 翻译的边界

### 3.1 边界规则

| 类别 | 来源 | 理由 |
|------|------|------|
| **纯布局组件**（Container、Row、Column、Padding、Center、SizedBox、Expanded） | **自研** | 这些组件是 CSS 属性的薄封装，与 Taffy 深度交互。WA 仓库中没有对应物——HTML 用 `<div>` + CSS 属性完成这些功能，不存在 `<wa-row>` 这样的组件 |
| **带视觉装饰的容器**（Card、Divider） | **WA 翻译** | WA 仓库有 `card/` 和 `divider/` 组件，包含预定义样式和 variant/size 属性 |

### 3.2 WA 翻译的准入条件

WA 翻译的装饰容器（Card、Divider 等）翻译为 WA 组件后，必须在 `rgui-components/src/` 下创建对应文件，并通过 wa-translate 技能的标准 7 步流程注册（`KNOWN_WIDGET_TYPES`、`paint_factory`、`default_layout_for_type` 等）。

## 4. 第 0 层——布局基础设施（自研）

> **定义：** 纯布局组件——本身无视觉外观，通过 CSS 属性控制子节点排列。纯自研，不走 WA 翻译。

### 4.0 为什么不需要 WidgetSpec 实现文件

框架使用 `.rgui` 声明式路径驱动 UI，不是 Rust 代码调用 `WidgetSpec::view()`。每个组件的核心行为通过框架层的字符串匹配处理：

| 框架层 | 对第 0 层组件的作用 |
|--------|-------------------|
| `KNOWN_WIDGET_TYPES` | `html!` 宏编译期验证标签名合法 |
| `default_layout_for_type` | 注入组件的默认 Taffy Style（flex 方向、gap、padding 等） |
| `extract_taffy_style` | 从 props 覆盖默认 CSS 属性 |
| `paint_factory` | 匹配组件名 → 返回空 Vec（无视觉外观） |

纯布局组件**不需要独立的 `.rs` 实现文件**——它们的存在形式就是上述 4 处字符串匹配条目。这不是设计缺陷，而是 `.rgui` 架构下的自然结果。

**无障碍行为：** 第 0 层容器节点在无障碍树中统一报告为 `AccessibilityRole::Group`，子节点通过 `WidgetView.children` 嵌套自动关联。框架层根据组件名（Container/Row/Column 等）自动注入角色，无需各组件单独定义。

> **注意：** 此规则仅适用于第 0 层纯布局组件。第 1 层 WA 翻译组件（Divider、Card）的 `paint()` 逻辑需要 `paint_factory` 调用 `WidgetSpec::paint()`，因此**仍然需要 `.rs` 实现文件**（见 §5）。

### 4.1 Container（通用容器）

**Web 参考：** `<div>`（无视觉外观的通用块级容器）

**设计思路：** 无视觉外观的通用容器。Row、Column、Padding、Center 都是 Container 的 CSS 预设组合。

**`default_layout_for_type` 注入：**

```rust
"Container" | "Card" | "Stack" => Style {
    display: Display::Flex,
    size: full_width_auto_height,
    ..Style::default()
}
```

**`paint_factory` 行为：** 返回空 Vec（不绘制任何内容）。

**支持的 CSS 属性（通过 `extract_taffy_style` 从 props 提取）：** `display`、`flex-direction`、`justify-content`、`align-items`、`gap`、`padding`、`margin`、`width`、`height`。

**属性值格式：** 字符串值（`"flex"`、`"row"`、`"column"`、`"center"`、`"stretch"` 等）→ `rgui_layout::mapping` 映射；数值（`8.0`、`16.0`）→ 逻辑像素。未在支持列表中声明的属性不生效。

**关键设计：** Container 的 children 由 `.rgui` 文件嵌套传入——`<Container><Button/></Container>`。Container 自身只负责设置 CSS 布局属性。

**验证标准：** 见 §7.2 Step 1。

---

### 4.2 Row（水平布局语法糖）

**Web 参考：** `display: flex; flex-direction: row`

**设计思路：** Container 的语法糖——预设 `flex-direction: row`。

**`default_layout_for_type` 注入：**

```rust
"Row" => Style {
    display: Display::Flex,
    flex_direction: FlexDirection::Row,
    size: full_width_auto_height,
    ..Style::default()
}
```

**`paint_factory` 行为：** 返回空 Vec。

**支持的 CSS 属性：** 同 Container（`gap`、`padding`、`justify-content`、`align-items` 等）。

---

### 4.3 Column（垂直布局语法糖）

**Web 参考：** `display: flex; flex-direction: column`

**设计思路：** Container 的语法糖——预设 `flex-direction: column`。与 Row 对称。

**`default_layout_for_type` 注入：**

```rust
"Column" => Style {
    display: Display::Flex,
    flex_direction: FlexDirection::Column,
    size: full_width_auto_height,
    ..Style::default()
}
```

**`paint_factory` 行为：** 返回空 Vec。

---

### 4.4 Padding（内边距语法糖）

**Web 参考：** `padding` CSS 属性

**设计思路：** Container 的语法糖——预设 `padding`，仅接受单个子节点。

**`default_layout_for_type` 注入：**

```rust
"Padding" => Style {
    display: Display::Flex,
    size: full_width_auto_height,
    padding: taffy::geometry::Rect {
        left: LengthPercentage::Length(16.0),
        right: LengthPercentage::Length(16.0),
        top: LengthPercentage::Length(16.0),
        bottom: LengthPercentage::Length(16.0),
    },
    ..Style::default()
}
```

**`paint_factory` 行为：** 返回空 Vec。

---

### 4.5 Center（居中布局语法糖）

**Web 参考：** `display: flex; align-items: center; justify-content: center`

**设计思路：** 预设 `align-items: center; justify-content: center`，仅接受单个子节点。

**`default_layout_for_type` 注入：**

```rust
"Center" => Style {
    display: Display::Flex,
    justify_content: Some(JustifyContent::Center),
    align_items: Some(AlignItems::Center),
    size: full_size,
    ..Style::default()
}
```

**`paint_factory` 行为：** 返回空 Vec。

---

### 4.6 Expanded（弹性扩展）

**Web 参考：** `flex-grow` CSS 属性

**设计思路：** 包装器组件——包裹单个子 widget，设置 `flex-grow: 1`，使其在父 flex 容器中占据剩余空间。**不是容器**——不创建新的 flex 上下文。

**`default_layout_for_type` 注入：**

```rust
"Expanded" => Style {
    flex_grow: 1.0,
    ..Style::default()
}
```

**`paint_factory` 行为：** 返回空 Vec。

---

### 4.7 SizedBox（固定尺寸约束）

**Web 参考：** `width` / `height` CSS 属性

**设计思路：** 包装子节点并施加可选尺寸约束。当 `width`/`height` prop 设置时强制约束为指定逻辑像素值；未设置时透传子节点自身约束，不影响布局。

**`default_layout_for_type` 注入：**

```rust
"SizedBox" => Style::default()  // 尺寸由 props 驱动，无预设
```

尺寸完全由 props 的 `width`/`height` 通过 `extract_taffy_style` 控制。

**`paint_factory` 行为：** 返回空 Vec。

## 5. 第 1 层——装饰与常用模式

> **准入条件：** 第 0 层全部完成后才能开始。这些组件通过 wa-translate 技能从 Web Awesome 翻译。

### 5.1 Divider（分隔线，WA 翻译）

**Web 参考：** `<hr>` 元素

**源：** `webawesome/src/components/divider/divider.ts`

**WidgetSpec 实现：**

| 维度 | 内容 |
|------|------|
| **State** | `direction: Axis`（Horizontal/Vertical）、`color: Option<Color>`、`thickness: Option<f64>` |
| **Message** | 空枚举（无交互消息） |
| **view()** | 返回无 children 的 WidgetView，在 props 中设置 `direction`、`color`、`thickness` 对应 CSS 属性 |
| **measure()** | 默认（返回 `Size::ZERO`，由父容器约束决定实际尺寸） |
| **paint()** | 绘制一条线：水平 = 宽度填满 + 高度 = thickness；垂直 = 高度填满 + 宽度 = thickness |
| **accessibility()** | 默认（`AccessibilityNode::none()`） |

**翻译注意：**
- WA 源组件属性映射：`@property() vertical: boolean` → `direction: Axis`
- 硬编码英文 label（框架仅支持拉丁文字）

---

### 5.2 Card（装饰容器，WA 翻译）

**Web 参考：** `<div>` + `box-shadow` + `border-radius`

**源：** `webawesome/src/components/card/card.ts`

> **前置条件：** Container 就位后，Card 在 Container 的布局能力之上叠加视觉装饰。

**WidgetSpec 实现：**

| 维度 | 内容 |
|------|------|
| **State** | `background_color: Option<Color>`、`border_radius: Option<f64>`、`border_width: Option<f64>`、`border_color: Option<Color>`、`elevation: Option<f64>` |
| **Message** | 空枚举（无交互消息） |
| **view()** | 与 Container 相同方式处理 children + 布局属性，额外设置视觉 CSS 属性（`background-color`、`border-radius` 等） |
| **measure()** | 默认（返回 `Size::ZERO`，布局由 Taffy 根据子节点计算） |
| **paint()** | 非空——绘制背景矩形（`fill_rect`）、边框（`fill_rect` 描边）。阴影可通过偏移若干像素的半透明 `fill_rect` 模拟 |
| **accessibility()** | 默认（`AccessibilityNode::none()`） |

**翻译注意：**
- WA 源组件有 `@slot`（header、footer、image）→ 翻译为 WidgetView.children 遍历判断
- `HasSlotController` → 遍历 children 判断 slot 内容是否存在

## 6. 与布局引擎的交互

### 6.1 CSS 属性 → Taffy 映射

所有容器组件依赖以下 CSS → Taffy 映射（已在 `rgui-layout` 中实现）：

| CSS 属性 | Taffy 字段 |
|----------|-----------|
| `display` | `Style.display` |
| `flex-direction` | `Style.flex_direction` |
| `flex-wrap` | `Style.flex_wrap` |
| `justify-content` | `Style.justify_content` |
| `align-items` | `Style.align_items` |
| `align-content` | `Style.align_content` |
| `gap` | `Style.gap` |
| `padding` | `Style.padding` |
| `margin` | `Style.margin` |
| `width` / `height` | `Style.size` |
| `min-width` / `min-height` | `Style.min_size` |
| `max-width` / `max-height` | `Style.max_size` |
| `flex-grow` | `Style.flex_grow` |

### 6.2 容器组件在布局管线中的位置

```
.rgui 文件 → parse_rgui_file() → WidgetView（含 CSS 布局属性 + children）
  → 框架从 props 提取布局键 → extract_taffy_style() → Taffy Style
  → Taffy::compute_layout(root, available_size)
  → 每个 widget 获得像素位置
  → paint_factory 分发绘制
```

### 6.3 注册要求（按组件层级区分）

#### 第 0 层（纯布局组件）— 无需 `.rs` 文件

Container、Row、Column、Padding、Center、Expanded、SizedBox 需要在 3 处框架层定义：

1. **`rgui-macros/src/html_codegen.rs`** — `KNOWN_WIDGET_TYPES` 添加名称
2. **`rgui-render/src/scene_build.rs`** — `default_layout_for_type` 添加 Taffy Style 预设
3. **`rgui/src/paint_factory.rs`** — 匹配组件名 → 返回空 Vec

#### 第 1 层（WA 翻译组件）— 需要 `.rs` 文件

Divider、Card 需要通过 wa-translate 技能的标准 7 步流程：

1. `rgui-components/src/<name>.rs` — WidgetSpec 实现（含 `paint()`）
2. `rgui-components/src/lib.rs` — `pub mod <name>;`
3. `rgui-macros/src/html_codegen.rs` — `KNOWN_WIDGET_TYPES` 添加名称
4. `rgui/src/paint_factory.rs` — match 分支创建实例 → `WidgetSpec::paint()` → `into_operations()`
5. `rgui-render/src/scene_build.rs` — `default_layout_for_type` 添加 match 分支

## 7. 实现顺序

### 7.1 推荐顺序

```
Step 0: SizedBox              ← 前置——在 default_layout_for_type 中定义布局条目
  │
Step 1: Container              ← 基石——验证 CSS 属性 → Taffy 布局的完整通路
  │
Step 2: Row + Column + Padding + Center + Expanded
  │                              ← 全部是 Container 的 CSS 预设组合，批量完成
  │
  ▼  ←─── 此时框架具备基本 flexbox 布局能力 ───→
  │
Step 3: Divider（WA 翻译）      ← 简单装饰组件，首次走 WA 翻译流程验证容器组件翻译
  │
Step 4: Card（WA 翻译）         ← 装饰容器，验证带 children 的 WA 组件翻译
```

### 7.2 每步验收标准

| 步骤 | 验收标准 |
|:----:|------|
| Step 0 | `cargo test` 全通过；SizedBox 包裹 WaButton 子节点，`width="200"` 约束生效——子节点布局宽度 = 200 逻辑像素 |
| Step 1 | Container + 3 个 WaButton 子节点（各有 `min_size: 80×36`），`gap="8"`，flex column 默认方向。相邻子节点中心距 = 36 + 8 = 44 逻辑像素 |
| Step 2 | Row > [WaButton, Column > [WaButton, WaButton]]，Row `gap="4"`，Column `gap="4"`。Row 内 Button 间距 = 4；Column 内 Button 间距 = 4；Row 高度 = Column 内部高度 |
| Step 3 | Divider 水平方向：高度 = thickness 默认值 1px；垂直方向：宽度 = thickness 默认值 1px。`cargo test` 全通过 |
| Step 4 | Card 包含 WaButton 子节点，`border_radius="8"`，背景色填充到圆角边界。`cargo test` 全通过 |

### 7.3 第 0 层完成后的效果

可以用声明式 HTML 编写 counter 示例的布局，不再需要一行 `Rect::new()`：

```html
<Column gap="8" padding="16">
  <Center>
    <WaButton label="+" onclick="increment" />
  </Center>
  <Row gap="4" justify-content="center">
    <WaButton label="Reset" onclick="reset" />
    <WaButton label="Count" variant="primary" />
  </Row>
</Column>
```

### 7.4 之后：恢复 WA 叶子组件翻译

第 0 层 + 第 1 层完成后，WA 翻译队列按以下顺序推进：

- P0 基础：icon → badge → spinner → avatar → breadcrumb + breadcrumb-item
- P0 表单：checkbox → switch → input → textarea → radio + radio-group → select
- P1 弹层/导航：tab + tab-group + tab-panel、menu + menu-item + menu-label
- P2 数据展示/反馈：tag、alert、skeleton、progress-bar...

弹层组件（dialog、drawer、dropdown、popup、tooltip）需要框架先提供浮层系统（定位、z-index、点击外部关闭），具体时机待框架能力就绪后确定。
