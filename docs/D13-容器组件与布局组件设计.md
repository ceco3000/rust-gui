## 1. 架构对比：Web vs rgui

### Web 的布局模型

Web 平台（HTML/CSS）的布局模型具有以下特征：

| 特征 | 说明 |
|------|------|
| **布局属性直接设置在元素上** | 任何 HTML 元素都可以通过 CSS 属性（`display`、`flex-direction`、`gap` 等）成为布局容器。没有独立的 Layout 对象 |
| **任何元素都可以成为容器** | `<div>` 默认是 block 容器；设置 `display: flex` 后即成为 flex 容器，可以包含子元素并控制其排列 |
| **Flexbox/Grid 算法驱动布局计算** | 浏览器引擎内置 flexbox 和 grid 布局算法，根据 CSS 属性计算每个元素的像素位置和尺寸 |
| **容器只设属性，引擎负责计算** | 开发者只需声明 CSS 属性（`justify-content: center`、`align-items: stretch`），浏览器引擎自动计算子元素位置 |

### rgui 的架构（与 Web 同构）

rgui 与 Web 共享相同的布局模型：

1. **布局是 CSS 驱动的**：`rgui-layout` crate 封装 Taffy，从 CSS 属性（`display`、`flex-direction`、`gap` 等）映射到 Taffy `Style`。布局引擎计算所有子 widget 的像素位置——这与浏览器引擎的角色相同
2. **WidgetView 已支持 children**：`WidgetView.children: Vec<WidgetView<M>>`。任何 widget 都可以有子 widget——框架天然支持容器语义，就像任何 HTML 元素都可以嵌套子元素
3. **容器组件只需设置 CSS 属性**：设置 `display: flex`、`flex-direction: column` 等属性后，Taffy 负责计算子节点位置——与 Web 开发者在 CSS 中声明 `display: flex` 后浏览器自动布局完全一致
4. **当前状态**：rgui-components 有 9 个叶子组件，但**没有任何容器组件**。所有示例（counter、crud）都用手工绝对坐标 `Rect::new(x, y, w, h)` 摆放元素——相当于用 `position: absolute; left: Xpx; top: Ypx` 写整个页面，缺少 flexbox 布局能力

### 与 Qt 的本质差异（仅作对比，不作为设计参考）

> **注意：** rgui 的布局模型与 Qt 完全不同。Qt 有 Widget 层次和 Layout 层次两套独立的体系——`QLayout` 是非 widget 的独立几何管理器对象，与它所管理的 widget 分离。而 Web/rgui 的布局属性直接设置在容器元素上，没有独立的 Layout 对象。rgui 的设计以 Web 为参照，不以 Qt 为参照。

### 组件对照表

| 功能 | HTML/CSS 等价 | rgui 实现 | `html!` 宏示例 |
|------|-------------|----------|---------------|
| 通用容器（有子元素） | `<div>`（block 容器） | **Container**——无视觉外观，设置 CSS 布局属性 | `<Container display="flex" flex-direction="row" gap="8">` |
| 水平布局 | `<div style="display: flex; flex-direction: row">` | **Row**——Container 预设 `flex-direction: row` | `<Row gap="4">` |
| 垂直布局 | `<div style="display: flex; flex-direction: column">` | **Column**——Container 预设 `flex-direction: column` | `<Column gap="8">` |
| 内边距 | `padding: 16px` CSS 属性 | **Padding**——Container 预设 `padding` | `<Padding padding="16">` |
| 居中 | `<div style="display: flex; align-items: center; justify-content: center">` | **Center**——Container 预设 `align-items: center; justify-content: center` | `<Center>` |
| 弹性扩展 | `flex-grow: 1` CSS 属性 | **Expanded**——子节点 `flex-grow: 1` | `<Expanded flex="1">` |
| 固定尺寸 | `width: 200px; height: 100px` CSS 属性 | **SizedBox**——强制约束子节点尺寸 | `<SizedBox width="200" height="100">` |
| 可滚动视口 | `overflow: auto` / `overflow: scroll` CSS 属性 | **ScrollView**——包装子 widget 提供滚动能力 | `<ScrollView>` |
| 重叠布局 | `position: absolute` + `z-index` | **Stack**——所有子元素显示，`position: absolute` + `z-index` | `<Stack>` |
| 装饰容器 | `<div>` + `box-shadow` + `border-radius` + `border` | **Card**——带视觉装饰（背景色、边框、圆角、阴影）的 Container | `<Card border-radius="8" elevation="2">` |
| 分隔线 | `<hr>` 元素 | **Divider**——水平或垂直分隔线 | `<Divider />` |
| 图片显示 | `<img>` 元素 | **Image**——显示位图/SVG | `<Image width="100" height="100" />` |
| 虚拟化列表 | 虚拟滚动列表（无原生 HTML 等价，JS 实现模式） | **ListView**——虚拟化可滚动列表，需 item 回收 | `<ListView item-height="40">` |

> **HTML 语法使用**：所有容器组件均可通过 `html!` 宏或 `.html` 文件以 HTML 声明式语法使用。HTML 标签名映射规则见 [D1 §13.4](./D1-组件模型与WidgetSpec设计.md#134-widgetregistry-标签查找规则)，CSS `class` 属性匹配规则见 [D4 §4.1](./D4-样式系统与rgss设计.md#41-选择器类型与-specificity)。

## 2. 设计原则

### 2.1 容器组件的共性

所有容器组件共享以下特征：

1. **不自己绘制内容**（除了 Card 的装饰背景和 Divider 的线条）：`paint()` 默认不产生任何绘制操作，或者只绘制装饰（边框、背景等）
2. **通过 CSS 属性控制布局**：每个容器组件的 `view()` 方法会在 `WidgetView.props` 中设置对应的 CSS 属性（`display`、`flex-direction`、`align-items`、`gap`、`padding` 等），框架通过 `rgui-layout` 将这些属性映射为 Taffy `Style`，执行布局计算
3. **子节点由 WidgetView.children 承载**：不需要特殊的数据结构，利用现有的 `WidgetView` 嵌套
4. **状态极简**：大多数容器组件的状态只包含构造参数（方向、间距等），无运行时可变状态

### 2.2 与 Taffy 交互流程

```
WidgetSpec::view() 返回 WidgetView
    │
    ├── props 中设置 layout CSS 属性（display, flex-direction, gap, padding, ...）
    │
    ▼
rgui-style 从 props 解析 → LayoutStyle 结构体
    │
    ▼
rgui-layout::to_taffy_style_from_layout() → Taffy Style
    │
    ▼
LayoutEngine::create_node(WidgetId, TaffyStyle, children) → LayoutNode
    │
    ▼
LayoutEngine::compute_layout(root, available_size)
    │
    ▼
每个 widget 获得像素位置（LayoutResult.position）
```

**关键：这一流程对容器组件和叶子组件完全相同。**容器组件的特殊性仅在于它们设置的 CSS 属性使 Taffy 将其视为 flex 容器。

### 2.3 容器组件 vs 叶子组件的区别

| 维度 | 叶子组件（Button、Label 等） | 容器组件（Container、Row 等） |
|------|--------------------------|---------------------------|
| `children` | 通常为空 | 有子 widget |
| `paint()` | 绘制自身内容（矩形、文本、图标） | 不绘制或仅绘制装饰（背景、边框） |
| `measure()` | 根据内容计算大小（如文本宽度） | 通常由 Taffy 根据子节点大小和约束计算 |
| CSS 属性侧重 | 视觉属性（color、background、border） | 布局属性（display、flex-direction、gap） |
| 状态 | 交互状态（pressed、disabled、value） | 构造参数（direction、spacing） |

## 3. 第 0 层——致命缺失组件

> **定义：** 没有这些组件，框架无法构建真实 App 的布局结构。所有示例当前只能用 `Rect::new(x, y, w, h)` 绝对坐标。

### 3.1 Container（通用容器）

**Web 参考：** `<div>`（无视觉外观的通用块级容器）

**设计思路：** 无视觉外观的通用容器。这是唯一需要与 `rgui-layout`/Taffy 深度交互的组件——其他所有布局组件都是 Container 的 CSS 预设组合。

**最小实现需求：**

| 维度 | 内容 |
|------|------|
| **State** | `display: Option<LayoutDisplay>`（默认 Flex）、`width: Option<f64>`、`height: Option<f64>`、`flex_direction: Option<FlexDirection>`、`justify_content: Option<JustifyContent>`、`align_items: Option<AlignItems>`、`align_content: Option<AlignContent>`、`gap: Option<f64>`、`padding: Option<f64>`、`margin: Option<f64>`、`flex_wrap: Option<FlexWrap>` |
| **Message** | 无（Container 不产生交互消息） |
| **view()** | 将 State 中各 `Option` 字段映射为 `WidgetView.props` 中的 CSS 属性键值对（如 `"display" → PropValue::str("flex")`、`"flex-direction" → PropValue::str("column")`）。`WidgetView.children` 来自外部传入 |
| **update()** | 无操作 |
| **paint()** | 空（无视觉外观） |
| **measure()** | 返回 `Size::ZERO`（布局由 Taffy 负责）或 `default_measure()` |

**关键设计决策：** Container 的 `view()` 不返回 children——children 由使用方在 `html!` 宏中通过嵌套传入。Container 只负责在自身 `WidgetView.props` 中设置 CSS 布局属性。

**与 Taffy 交互：** 框架从 Container 的 `WidgetView.props` 提取布局相关键 → 构造 `LayoutStyle` → `to_taffy_style_from_layout()` → 创建 Taffy 节点（`display: Flex` + 其他属性）

**验证标准：** Container 包含 3 个子 Button，窗口宽度 400px 时，子 Button 按 flex row 排列且间距正确。

---

### 3.2 Row（水平布局语法糖）

**Web 参考：** `display: flex; flex-direction: row`

**设计思路：** Container 的语法糖——预设 `display: flex; flex-direction: row`。

**最小实现需求：**

| 维度 | 内容 |
|------|------|
| **State** | `main_axis_alignment: Option<JustifyContent>`（默认 Start）、`cross_axis_alignment: Option<AlignItems>`（默认 Stretch）、`gap: Option<f64>`（默认 0.0） |
| **Message** | 无 |
| **view()** | 构造一个带 `display: flex` + `flex-direction: row` 的 Container-style `WidgetView`，将 alignment 和 gap 映射为对应 CSS 属性 |
| **paint()** | 空 |

**实现方式：** Row 可以作为独立的 `WidgetSpec` 实现，也可以在 `html!` 宏层面展开为 Container + 预设属性。建议**先作为独立 WidgetSpec 实现**（简单直观），后续评估是否需要在宏层面优化。

---

### 3.3 Column（垂直布局语法糖）

**Web 参考：** `display: flex; flex-direction: column`

**设计思路：** Container 的语法糖——预设 `display: flex; flex-direction: column`。与 Row 对称。

**最小实现需求：** 与 Row 相同，仅 `flex-direction` 预设为 `column`。

---

### 3.4 Padding（内边距语法糖）

**Web 参考：** `padding` CSS 属性

**设计思路：** Container 的语法糖——预设 `padding`，仅接受**单个子节点**。

**最小实现需求：**

| 维度 | 内容 |
|------|------|
| **State** | `padding: f64`（四边相同） |
| **Message** | 无 |
| **view()** | 返回 Container-style `WidgetView`，设置 `padding` CSS 属性，包裹单个 child |
| **paint()** | 空 |

---

### 3.5 Center（居中布局语法糖）

**Web 参考：** `display: flex; align-items: center; justify-content: center`

**设计思路：** Container 的语法糖——预设 `align-items: center; justify-content: center`。仅接受单个子节点。

**最小实现需求：**

| 维度 | 内容 |
|------|------|
| **State** | 无（纯布局） |
| **view()** | 返回 Container-style `WidgetView`，设置 `display: flex; align-items: center; justify-content: center` |
| **paint()** | 空 |

---

### 3.6 Expanded（弹性扩展子节点）

**Web 参考：** `flex-grow` CSS 属性

**设计思路：** 这是一个**包装器组件**——包裹单个子 widget，设置 `flex-grow: 1`，使其在父 flex 容器中占据剩余空间。**不是 Container**，而是叶子节点上的包装。

**最小实现需求：**

| 维度 | 内容 |
|------|------|
| **State** | `flex: f64`（默认 1.0，即 flex-grow 值） |
| **Message** | 无 |
| **view()** | 包裹单个 child，在自身的 `WidgetView.props` 中设置 `flex-grow` 对应的 CSS 属性 |
| **paint()** | 空 |

**关键设计：** Expanded **不是容器**——它不创建新的 flex 上下文，而是修改**自身在父容器中的布局行为**。框架需识别 `flex-grow` 属性并将其传播到 Taffy 节点。

---

### 3.7 SizedBox（固定尺寸约束）

**Web 参考：** `width` / `height` CSS 属性

**设计思路：** 强制约束子节点的宽度和/或高度为指定值。如果某个维度为 `None`，则在该维度上不施加约束。

**最小实现需求：**

| 维度 | 内容 |
|------|------|
| **State** | `width: Option<f64>`、`height: Option<f64>` |
| **view()** | 包裹单个 child，在自身的 `WidgetView.props` 中设置 `width`/`height` CSS 属性 |
| **paint()** | 空 |

## 4. 第 1 层——常见 App 结构组件

> **定义：** 构建常见 App UI 结构必需的组件。没有它们也能渲染，但无法构建真实应用的典型界面模式。

### 4.1 ScrollView（可滚动视口）

**Web 参考：** `overflow: auto` / `overflow: scroll` CSS 属性

**设计思路：** 可滚动视口包装任意子 widget。核心概念：视口（viewport，可见区域）、内容区域（content，可能大于视口）、滚动条（scrollbar）、滚动策略（scroll policy）。

**最小实现需求：**

| 维度 | 内容 |
|------|------|
| **State** | `scroll_x: f64`（水平滚动位置，px）、`scroll_y: f64`（垂直滚动位置，px）、`scroll_policy: ScrollPolicy`（Always/AsNeeded/Never） |
| **Message** | `ScrollChanged { x: f64, y: f64 }`（滚动位置改变） |
| **view()** | 包裹单个 child widget（内容区域） |
| **在框架中的特殊处理** | 框架需识别 ScrollView 并：① 在 measure 阶段对内容区域使用松散约束（无上限）；② 在 paint 阶段应用 `translate(-scroll_x, -scroll_y)` 偏移裁剪渲染 |
| **paint()** | 可绘制滚动条和视口裁剪矩形 |

**关键实现点：**
- 滚动条暂可使用简单矩形占位（阶段 0 最小可用即可，阶段 1+ 美化为 Native 风格）
- 鼠标滚轮事件需路由到 ScrollView 更新 `scroll_y`
- 裁剪使用 `PaintContext` 的 clip rect 能力或 Vello 的 clip 原语

**复杂度评估：** 这是第 1 层最复杂的组件，因为在框架层需要裁剪/坐标变换支持。

---

### 4.2 Stack（重叠布局）

**Web 参考：** `position: absolute` + `z-index`

**设计思路：** 所有子元素使用 `position: absolute`，重叠在同一区域。由 `z-index` 属性控制绘制顺序。与 Web 的绝对定位层叠上下文模型一致。

**最小实现需求：**

| 维度 | 内容 |
|------|------|
| **State** | `alignment: Option<AlignItems>`（默认 top-left） |
| **view()** | 包裹多个 children，在 CSS 属性中标记 `position: absolute` 的子元素定位方式 |
| **paint()** | 空 |

**关键设计：** Stack 的子元素需要 `position: absolute` 的定位能力。这要求布局引擎支持绝对定位——当前 Taffy 封装可能尚未支持。最简单的最小实现：所有子元素从 Stack 的 (0, 0) 位置开始布局，由子元素自身样式控制偏移。

**第一阶段最小实现策略：** Stack 直接将所有子元素放置在它自己的 origin（0, 0），子元素用自己的 `margin`/绝对坐标偏移。z-index 通过 children 数组的顺序决定。

---

### 4.3 Card（装饰容器）

**Web 参考：** `<div>` + `box-shadow` + `border-radius` + `border`

**设计思路：** 带视觉装饰的 Container。本质上是 Container + 预定义视觉样式（背景色、边框、圆角、阴影）。

**最小实现需求：**

| 维度 | 内容 |
|------|------|
| **State** | `background_color: Option<Color>`（默认白色）、`border_radius: Option<f64>`（默认 8.0）、`border_width: Option<f64>`（默认 1.0）、`border_color: Option<Color>`（默认浅灰）、`elevation: Option<f64>`（阴影高度，默认 2.0） |
| **view()** | 与 Container 相同（CSS 布局属性 + children），额外设置 `background-color`、`border-radius`、`border-width`、`border-color`、`box-shadow` 等视觉 CSS 属性 |
| **paint()** | **非空**——绘制背景矩形（填充 `background_color`）、边框（描边 `border_color`）、阴影 |

**与 Container 的关系：** Card 是 Container 的子集——Container 关注布局，Card 关注装饰。Card 在 Container 的布局能力之上叠加视觉样式。

---

### 4.4 Divider（分隔线）

**Web 参考：** `<hr>` 元素

**设计思路：** 水平或垂直分隔线。零交互、零子节点。

**最小实现需求：**

| 维度 | 内容 |
|------|------|
| **State** | `direction: Axis`（Horizontal / Vertical）、`color: Option<Color>`（默认浅灰）、`thickness: Option<f64>`（默认 1.0 px） |
| **view()** | 无 children，设置 `width`/`height` 或依赖父容器拉伸 |
| **paint()** | 绘制一条线（fill_rect）：水平 = 宽度填满 + 高度 = thickness；垂直 = 高度填满 + 宽度 = thickness |

---

### 4.5 Image（图片显示）

**Web 参考：** `<img>` 元素

**设计思路：** 显示位图（PNG、JPEG、WebP）或 SVG。阶段 0 最小实现仅支持内存中的 RGBA 像素缓冲。

**最小实现需求：**

| 维度 | 内容 |
|------|------|
| **State** | `image_data: Option<Arc<[u8]>>`（RGBA 像素缓冲）、`width: u32`、`height: u32`、`fit: ImageFit`（Fill/Contain/Cover/None） |
| **Message** | 无（阶段 0） |
| **view()** | 无 children |
| **paint()** | 通过 `PaintContext` 上传图像到 GPU 纹理，绘制纹理矩形 |

**关键依赖：** 需要 `RenderBackend::update_texture()`（已在 R04a 中实现），将像素缓冲上传到 GPU 并获取纹理 ID。

**阶段 0 范围外：** 文件加载（需要 image crate 解码）、SVG 渲染、网络图片。

---

### 4.6 ListView（虚拟化列表）

**Web 参考：** 虚拟滚动列表（无原生 HTML 等价，JavaScript 实现模式，如 react-window、vue-virtual-scroller）

**设计思路：** 虚拟化可滚动列表——仅渲染可见区域的 item，回收离开视口的 item。适用于大量数据（1000+ 项）。

**最小实现需求：**

| 维度 | 内容 |
|------|------|
| **State** | `items: Vec<WidgetView<M>>`（所有 item 的视图模板）、`scroll_offset: f64`（垂直滚动偏移）、`item_height: f64`（每项高度，阶段 0 假设等高） |
| **Message** | `Scrolled(f64)`（滚动位置改变） |
| **view()** | 无外部 children（items 通过 state 传入） |
| **特殊处理** | 框架需识别 ListView 并在 `view()` 重建阶段仅生成可见 item 的新 WidgetView |

**阶段 0 最小实现策略（简化）：**
1. 假设所有 item 等高（`item_height`）
2. 根据视口高度和 scroll_offset 计算可见范围 [first_visible, last_visible]
3. 仅对可见 item 调用 `view()` 生成 WidgetView
4. 离开视口的 item 不参与 paint

**复杂度评估：** ListView 是第 1 层最复杂的组件（仅次于 ScrollView），需要框架层的回收和懒渲染支持。阶段 0 可用简化版（等高 + 线性扫描），完整虚拟化（不等高、回收池、增量更新）属于阶段 1+。

## 5. 与布局引擎的交互契约

### 5.1 容器组件在布局管线中的位置

```
1. WidgetSpec::view() 返回 WidgetView（含布局 CSS 属性 + children）
2. 框架从 WidgetView.props 提取布局相关键 → 构造 LayoutStyle
3. rgui-layout::to_taffy_style_from_layout() → Taffy Style
4. LayoutEngine::create_node(widget_id, taffy_style, children_nodes)
5. LayoutEngine::compute_layout(root, available_size)
6. 每个 widget 从 LayoutEngine::get_layout(widget_id) 获取像素位置
7. 渲染阶段使用像素位置（paint() 中的 PaintContext.bounds）
```

### 5.2 容器组件需要框架支持的 CSS 属性

所有容器组件共享以下 CSS → Taffy 映射（已在 `rgui-layout::mapping` 中实现）：

| CSS 属性 | Taffy 字段 | 已有映射 |
|----------|-----------|---------|
| `display` (flex/grid/block/none) | `Style.display` | ✅ |
| `flex-direction` (row/column/...) | `Style.flex_direction` | ✅ |
| `justify-content` | `Style.justify_content` | ✅ |
| `align-items` | `Style.align_items` | ✅ |
| `align-content` | `Style.align_content` | ✅ |
| `gap` | `Style.gap` | ✅ |
| `padding` | `Style.padding` | ✅ |
| `margin` | `Style.margin` | ✅ |
| `width` / `height` | `Style.size` | ✅ |
| `min-width` / `min-height` | `Style.min_size` | ✅ |
| `max-width` / `max-height` | `Style.max_size` | ✅ |
| `flex-grow` | `Style.flex_grow` | ✅（LayoutStyle 已有字段） |
| `flex-shrink` | `Style.flex_shrink` | ✅（LayoutStyle 已有字段） |
| `flex-wrap` | `Style.flex_wrap` | ✅（LayoutStyle 已有字段） |
| `position` (absolute/relative) | Taffy `Style.position` | ⚠️ 需在 mapping 中新增 |

### 5.3 需要新增的 CSS 属性映射

| CSS 属性 | 用途 | Taffy 字段 |
|----------|------|-----------|
| `position: absolute` | Stack/Overlay 中绝对定位 | `Style.position = Position::Absolute` |
| `z-index` | Stack 中绘制顺序 | 框架层 z-index → SceneGraph 层级排序 |

**`position: absolute`** 在第 1 层实现 Stack 时需要。如果阶段 0 暂不实现 Stack 的绝对定位，可通过手动坐标偏移模拟。

## 6. 实现顺序与优先级

### 6.1 推荐实现顺序

```
第 1 步：Container（验证与 Taffy 的连线）
    │
    ▼
第 2 步：Row + Column + Padding + Center + SizedBox + Expanded
    （全是 Container 的 CSS 预设组合，实现极快）
    │
    ▼  ←─── 此时框架已具备基本布局能力 ───→
    │
第 3 步：Card + Divider（简单装饰组件，验证 paint 装饰链路）
    │
第 4 步：Image（验证 GPU 纹理上传链路）
    │
第 5 步：ScrollView（需要框架层裁剪/坐标变换支持）
    │
第 6 步：Stack（需要 position: absolute 映射）
    │
第 7 步：ListView（需要虚拟化渲染支持）
```

### 6.2 优先级分档

| 优先级 | 组件 | 标准 |
|--------|------|------|
| **P0** | Container、Row、Column、Padding、Center、Expanded、SizedBox | 没有这些无法构建真实 App 布局 |
| **P0** | Card、Divider | 构建 App 需要基本装饰 |
| **P1** | Image、ScrollView | 常见 App 模式，但不是阻塞项 |
| **P1** | Stack | 有用但非必须 |
| **P2** | ListView | 复杂，可后续迭代 |

### 6.3 关键里程碑

**容器 MVP（P0 全部完成）：** 可以用 Row/Column + Padding/Center/Expanded/SizedBox + Card/Divider 构建 counter/crud 示例的布局，不再需要手工绝对坐标（`Rect::new(x, y, w, h)`）。
