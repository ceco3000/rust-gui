## 1. 设计目标与范围

### 1.1 本文档解决什么问题

本文档明确以下问题：

1. rgui 内部哪些层使用逻辑像素，哪些层保留平台原始窗口坐标或渲染物理像素。
2. 鼠标移动、按下、抬起、窗口缩放变化和窗口尺寸变化应在何处做坐标归一化。
3. Qt 风格的窗口坐标、接收者局部坐标和原始输入证据在当前项目中的正式术语是什么。
4. 自动化点击、自动化 hover、平台事件回放和命中测试应如何统一到同一坐标契约。
5. 后续新增平台、新增局部变换或新增自动化能力时，应遵守哪些工程门禁。

### 1.2 不在本文档范围内

- 不重新定义 D5 的完整事件系统设计。
- 不重新设计 D3 的渲染后端 API。
- 不承诺当前仓库已经支持任意仿射变换下的精确命中测试。
- 不把 macOS 当前结论外推为所有 `winit` 版本、所有平台、所有窗口后端的通用真理。

### 1.3 设计原则

1. **组件层只看逻辑像素**：组件、布局、命中测试、交互注册的输入输出默认全部是逻辑像素。
2. **平台边界一次归一化**：原始平台事件只允许在边界处转换为逻辑坐标，进入框架内部后禁止再次重复换算。
3. **渲染边界一次放大**：逻辑坐标只允许在渲染后端边界结合 `scale_factor` 放大为物理像素。
4. **运行时证据优先**：平台实际行为与外部文档不一致时，以仓库当前运行时证据和自动化回归结果为准。
5. **同一事件链路同一坐标**：`MouseMove`、`MouseDown`、`MouseUp`、hover 命中、click 命中必须共享同一套窗口逻辑坐标语义。

## 2. 结论摘要

### 2.1 当前统一结论

| 主题 | 结论 |
|------|------|
| rgui 内部标准坐标 | **逻辑像素**。`Point`、`Size`、`Rect`、`BoxConstraints` 都按逻辑像素解释 |
| 渲染后端尺寸 | **物理像素**。`RenderParams.width/height` 是物理像素，`scale_factor` 用于把逻辑绘制坐标映射到物理表面 |
| 鼠标事件主坐标 | **窗口逻辑坐标**。统一通过 `MouseEventCoords.window_logical` 表达 |
| 组件内部交互坐标 | **接收者局部逻辑坐标**。命中成功后通过 `MouseEventCoords.local_logical` 表达 |
| 平台原始输入证据 | 通过 `MouseInputOrigin::{PlatformWindowEvent, PhysicalInjection}.raw_window_position` 保留，仅用于归一化、调试、回放和回归断言 |
| `WindowResized` 暴露给组件层 | **逻辑尺寸**，不能把窗口物理像素直接透传给组件层 |
| `ScaleFactorChanged` | 必须同步内部 `scale_factor`，并基于缓存的 `last_raw_window_position` 重算 `mouse_window_position` |
| macOS Retina 当前结论 | 当前实现链路下，原始窗口输入再除一次 `scale_factor` 会造成双重缩放；macOS 路径必须直接按当前数值作为 `window_logical` 使用 |
| 自动化点击 / hover | 允许同时提供“逻辑注入”和“平台原始窗口注入”接口，但最终都必须收敛到同一逻辑命中结果 |
| 局部变换支持现状 | 当前命中测试对祖先布局偏移和滚动偏移链路已有回归保证；对任意旋转、缩放等一般仿射变换尚未形成完整命中链路 |

### 2.2 最核心的工程红线

1. 不允许在组件层出现“有的 rect 是逻辑像素，有的点击点是平台原始坐标”的混用状态。
2. 不允许 `MouseMove`、`MouseDown`、`MouseUp` 三条路径各自独立做 DPI 换算。
3. 不允许为了修一个平台问题，破坏另一平台的统一语义，而不补齐自动化对照测试。
4. 不允许引入新的局部视觉变换，却继续沿用未变换的交互矩形。

### 2.3 Qt 坐标术语与正式语义

Qt 坐标体系在 rgui 中以“窗口逻辑坐标 + 接收者局部坐标 + 平台原始窗口坐标证据”的形式落地，正式术语如下：

| rgui 术语 | 当前字段 / API | Qt 对齐语义 | 工程要求 |
|------|------|------|------|
| 窗口逻辑坐标 | `MouseEventCoords.window_logical`、`mouse_window_position` | 窗口级统一逻辑坐标基线 | 命中测试、hover、click、拖拽、日志全部以它为主坐标 |
| 接收者局部坐标 | `MouseEventCoords.local_logical` | 命中接收者后的局部坐标，等价于 Qt 风格 receiver-local position | 只有在命中具体接收者后才可读取，不能与窗口绝对坐标直接比较 |
| 平台原始窗口坐标证据 | `MouseInputOrigin::{PlatformWindowEvent, PhysicalInjection}.raw_window_position` | 平台输入或自动化注入的原始窗口坐标 | 只允许用于归一化、调试、回放和回归断言，不能直接参与高层命中测试 |

补充约束：

1. 当前项目尚未把“屏幕全局坐标”作为高层稳定 API 暴露；后续若补充，必须新增独立字段，不得复用 `raw_window_position`。
2. 旧单字段 `position` 不再是正式规范术语；涉及窗口坐标时使用 `window_logical`，涉及局部坐标时使用 `local_logical`。
3. 任何新增 API 若同时暴露多个坐标参考系，字段名必须显式携带 `window_`、`local_`、`raw_`、`logical` 或 `physical` 语义。

## 3. Qt 一致性坐标模型

### 3.1 坐标层级总览

当前仓库可分为 5 个坐标层：

| 层级 | 代表对象 | 单位 | 当前职责 |
|------|---------|------|---------|
| 平台原始输入层 | `winit::WindowEvent`、`raw_window_position` | 平台相关，原始窗口坐标 | 接收鼠标、键盘、缩放和尺寸变化 |
| 框架输入归一化层 | `normalize_platform_window_point()`、`AppHandler::sync_pointer_from_platform_window_event()` | 逻辑像素 | 把平台原始窗口输入统一转换为框架内部可用坐标 |
| 布局与命中测试层 | `LayoutEngine::absolute_position()`、交互 `Rect`、`find_widget_at_point()` | 逻辑像素 | 形成组件边界、命中测试、交互注册 |
| 场景构建层 | `SceneGraph`、`DrawCommand`、`PushTransform` | 逻辑像素 | 组织绘制命令、裁剪、滚动平移 |
| 渲染后端层 | `RenderParams { width, height, scale_factor }` | 表面尺寸为物理像素，绘制输入为逻辑像素 | 最终把逻辑绘制结果提交到物理表面 |

### 3.2 当前核心类型契约

`rgui-core::geometry` 已明确：

```rust
//! | 组件层（paint()、measure()、hit_test()） | 逻辑像素 |
//! | 平台适配层（rgui-platform 事件转换）   | 物理/原始窗口输入 -> 逻辑转换 |
//! | 渲染后端边界（RenderBackend trait）    | 物理像素 |
```

这意味着：

1. `Point`、`Size`、`Rect` 在框架内部默认表示逻辑像素。
2. `LayoutStyle.width/height/gap/padding/margin`、文本字号、边框宽度等都以逻辑像素解释。
3. `Rect::contains()`、命中测试、hover 判断、click 判断都必须基于逻辑像素。

### 3.3 App 运行时中的双坐标缓存

当前 `AppHandler` 同时维护两套与鼠标相关的数据：

1. `last_raw_window_position`：最近一次平台窗口原始坐标，只用于平台归一化复算、调试日志和自动化回放证据。
2. `mouse_window_position`：归一化后的窗口逻辑坐标，供 hover、click、事件分发与命中测试使用。

这套设计的目的不是让业务层同时读写两种单位，而是：

- 仅在平台边界保留“原始输入证据”。
- 框架内部热路径统一消费 `mouse_window_position`。
- `ScaleFactorChanged` 到来时，可以用缓存的 `last_raw_window_position` 重新计算逻辑位置，避免继续使用旧缩放因子下的陈旧结果。

### 3.4 窗口尺寸与渲染尺寸语义

当前实现中，尺寸语义分成两类：

| 对象 | 单位 | 说明 |
|------|------|------|
| `self.width` / `self.height` | 物理像素 | 用于创建/调整渲染表面，传给 `RenderParams` |
| `Event::WindowResized { width, height }` | 逻辑像素 | 传给组件层，供布局和业务逻辑使用 |
| `App::scale_factor()` | 比例值 | 逻辑像素到物理像素的缩放倍率 |

因此，`WindowResized` 与 `RenderParams` 不能复用同一对宽高字段。一个面向组件层，一个面向后端层，两者单位不同但都合法。

### 3.5 当前事件归一化链路

#### 鼠标移动

1. 平台产生 `WindowEvent::CursorMoved`。
2. `normalize_platform_window_point(raw_window_position, scale_factor)` 将平台输入收敛为 `window_logical`。
3. `AppHandler::sync_pointer_from_platform_window_event()` 更新 `mouse_window_position` 与 `last_raw_window_position`。
4. 生成 `Event::MouseMove { coords: MouseEventCoords, delta_window_logical, ... }`。
5. 同一逻辑点继续驱动 hover 更新与后续命中测试。

#### 鼠标按下 / 抬起

1. 平台产生 `WindowEvent::MouseInput`。
2. 不重新读取或重新换算位置。
3. 直接使用缓存的 `self.mouse_window_position`。
4. 生成 `Event::MouseDown { coords, ... }` / `Event::MouseUp { coords, ... }`。

该设计的关键价值在于：移动和点击不再来自两套独立坐标管线，消除了“hover 正确但 click 错误”或“click 正确但 MouseMove 错误”的常见分叉问题。

#### 窗口尺寸变化

1. 平台产生 `WindowEvent::Resized(physical_size)`。
2. `logical_window_size_from_physical_size(width, height, scale_factor)` 用当前 `scale_factor` 换算为逻辑尺寸。
3. 对组件层推送 `Event::WindowResized { width, height }`，语义为窗口逻辑尺寸。

#### DPI 变化

1. 平台产生 `WindowEvent::ScaleFactorChanged`。
2. `sync_scale_factor(new_scale_factor)` 更新内部缩放因子。
3. 若存在 `last_raw_window_position`，立即重新计算 `mouse_window_position`。
4. 更新 hover 状态，必要时调整后端尺寸。
5. 向组件层推送 `Event::ScaleFactorChanged { scale_factor }`。

## 4. macOS Retina 问题结论

### 4.1 问题现象

在 `one-accordion` 的 macOS Retina 场景中，曾出现如下问题：

1. 鼠标视觉上位于组件 header 区域。
2. 实际 click / hover 命中却偏向左上角。
3. 偏移量与 `scale_factor = 2` 的缩放关系一致。

这说明问题不是随机误差，而是系统性的坐标空间误用。

### 4.2 已验证结论

当前仓库的工程结论是：在 macOS Retina 的当前运行时链路中，平台原始窗口输入若继续除以 `scale_factor`，会发生双重缩放，导致命中点被错误压缩回左上角。

### 4.3 macOS Retina 的最终规范

1. 对 macOS 当前路径，`normalize_platform_window_point()` 必须返回 `CoordinateNormalization::PlatformNativeLogical`，不得再次除以 `scale_factor`。
2. `WindowResized` 仍然通过物理尺寸结合 `scale_factor` 产生逻辑尺寸。
3. 渲染表面仍使用物理尺寸，不能因为输入侧是逻辑坐标就把渲染尺寸也改成逻辑尺寸。
4. 自动化“平台原始窗口注入”在 macOS 当前测试语义下，数值上应与视觉逻辑点一致，不得强行乘以 `scale_factor`。

### 4.4 结论边界

本结论只覆盖以下范围：

- 当前仓库版本。
- 当前 `normalize_platform_window_point()` 的平台分支策略。
- 当前 `one-accordion` 回归测试覆盖的交互模型。
- 当前 macOS Retina 运行时环境。

本结论不自动推出：

- 所有 macOS 应用都应该这样处理。
- 所有 `winit` 事件都已经完全是逻辑坐标。
- 未来引入新的窗口后端或输入源后仍不需要复核。

## 5. 不同平台与不同坐标空间的处理流程

### 5.1 标准流程总图

```text
平台原始窗口坐标
  -> 平台边界归一化
  -> 框架窗口逻辑坐标 window_logical
  -> hover / click / hit test / widget rect 统一使用
  -> 命中后恢复 local_logical
  -> SceneGraph 保持逻辑坐标
  -> RenderBackend 结合 scale_factor 输出到物理表面
```

### 5.2 macOS 流程

1. 平台回调给出原始窗口位置 `(x, y)`。
2. `normalize_platform_window_point()` 直接构造 `window_logical`。
3. `last_raw_window_position` 保留原始数值供后续复算。
4. `mouse_window_position` 作为 hover、click、事件分发的唯一逻辑输入。

### 5.3 非 macOS 流程

1. 平台位置进入 `normalize_platform_window_point()`。
2. 使用 `raw_window_position / scale_factor` 归一化为 `window_logical`。
3. 其余规则与 macOS 保持一致：组件层只看逻辑坐标、`WindowResized` 暴露逻辑尺寸、`ScaleFactorChanged` 后重算缓存逻辑点。

### 5.4 不同坐标空间的职责边界

| 坐标空间 | 允许出现的位置 | 禁止事项 |
|---------|---------------|---------|
| 平台原始窗口坐标 | 平台事件回调、自动化原始注入接口、回放断言 | 不能直接拿去做命中测试 |
| 逻辑窗口坐标 | `mouse_window_position`、`MouseEventCoords.window_logical`、命中测试、布局绝对位置 | 不能再二次除以 `scale_factor` |
| 组件局部坐标 | `MouseEventCoords.local_logical`、内部子命中测试 | 不能直接与全局窗口坐标比较 |
| 渲染物理坐标 | `RenderParams`、后端编码、表面提交 | 不能透传回组件层当作布局尺寸 |

### 5.5 事件类型的处理规范

| 事件 | 输入来源 | 框架内部标准单位 | 处理要求 |
|------|---------|-----------------|---------|
| `MouseMove` | 平台位置 | `coords.window_logical` 为逻辑像素 | 在边界归一化，并保留 `origin` |
| `MouseDown` / `MouseUp` | 平台按钮状态 + 缓存位置 | `coords.window_logical` 为逻辑像素 | 复用缓存 `mouse_window_position` |
| `MouseWheel` | 平台滚轮与当前鼠标位置 | 鼠标位置为逻辑像素 | 与 hover / click 保持同一位置语义 |
| `WindowResized` | 物理尺寸 | 逻辑尺寸 | 组件层只接收逻辑尺寸 |
| `ScaleFactorChanged` | 缩放比例变化 | 比例值 | 必须触发缓存逻辑位置重算 |

## 6. 自动化点击与 Hover 工程规范

### 6.1 自动化目标

自动化不是为了“模拟某个平台的所有输入细节”，而是为了验证以下不变式：

1. 视觉上落在组件中心的点，hover 与 click 必须命中同一组件。
2. `scale_factor = 1` 与 HiDPI 场景下的交互行为必须一致。
3. 平台原始窗口注入路径和逻辑坐标注入路径最终必须汇聚到同一命中结果。

### 6.2 当前 Harness 契约

`InteractionAutomationHarness` 当前提供以下核心接口：

1. `hit_test_logical(position)`。
2. `inject_hover_logical(position)`。
3. `inject_hover_platform_window_raw(position)`。
4. `inject_click_logical(position)`。
5. `inject_click_platform_window_raw(position)`。
6. `replay_cursor_moved_platform_window_raw(position)`。
7. `replay_left_click_platform_window_raw(position)`。

兼容性别名 `inject_hover_physical()` / `inject_click_physical()` 仍可用，但从本规范开始，新增文档、测试与辅助函数命名应优先使用更明确的 `*_platform_window_raw`。

### 6.3 平台原始窗口注入的当前平台规范

| 平台 | 自动化“平台原始窗口注入”点生成规则 |
|------|--------------------------|
| macOS | 当前测试中直接使用视觉逻辑点数值，不再乘 `scale_factor` |
| 非 macOS | 用逻辑点乘以 `scale_factor`，构造平台原始窗口输入点 |

这是当前仓库已验证通过的规范，而不是抽象教条。若未来平台适配层统一后发生变化，必须同步修改 Harness、迁移说明与 D14。

### 6.4 自动化用例最低要求

新增或修改鼠标坐标链路时，至少补齐以下回归：

1. 同一目标点的 `hit_test_logical`、`inject_hover_platform_window_raw`、`inject_click_platform_window_raw` 结果一致。
2. `scale_factor = 1` 与 HiDPI 场景的交互结果一致。
3. hover 命中与 click 命中一致。
4. 点击后实际状态变化与命中目标一致。
5. `window_logical`、`local_logical` 与 `raw_window_position` 三者关系可断言。

## 7. 组件局部变换与命中测试规范

### 7.1 当前已正确支持的部分

当前命中测试注册主要依赖：

1. `LayoutEngine::get_layout(widget_id)` 取得节点本地尺寸。
2. `LayoutEngine::absolute_position(widget_id)` 沿父链累加祖先偏移，得到窗口绝对位置。
3. 用 `(abs_pos, size)` 形成交互 `Rect`。
4. 命中后通过窗口到局部的恢复链路产出 `local_logical`。

因此，当前仓库已经明确支持：

- 由布局产生的祖先偏移。
- 普通容器嵌套下的绝对位置累加。
- 滚动偏移场景下窗口逻辑坐标到局部坐标的一致断言。

### 7.2 当前未承诺支持的部分

当前文档与实现都不能宣称以下场景已经完整支持：

1. 任意旋转后的精确命中测试。
2. 任意缩放后的局部命中逆变换。
3. 斜切、矩阵组合、嵌套变换栈下的统一输入逆映射。

### 7.3 局部变换的工程规范

1. **视觉变换与交互变换必须同源**：视觉位置发生变化时，交互区域必须来自同一变换源。
2. **仅有祖先偏移时，使用绝对位置累加**：窗口逻辑点直接做全局 `Rect::contains()` 即可。
3. **涉及滚动偏移时，命中区域必须显式纳入滚动量**：只做视觉滚动、不做交互滚动补偿，属于严重 bug。
4. **引入任意仿射变换前，先补齐逆变换命中模型**：包括全局点到局部点的逆矩阵变换、裁剪顺序、嵌套变换组合规则和自动化验证。

## 8. 工程约束与编码规范

### 8.1 命名规范

凡是新增字段、参数或局部变量，只要同时可能出现逻辑像素和平台原始窗口坐标 / 物理像素，必须显式命名：

- `*_window_logical`
- `*_local_logical`
- `*_raw_window_position`
- `*_physical`
- `scale_factor`

禁止使用无单位语义的模糊命名，例如 `position`、`x`、`y`、`width`、`height`，除非所在作用域已被文档明确限定为单一坐标空间。

### 8.2 注释规范

坐标转换点必须写清楚三件事：

1. 输入坐标空间。
2. 输出坐标空间。
3. 为什么必须在这里转换，而不是在其他地方转换。

### 8.3 单一转换点规范

以下转换必须只在单一点发生：

| 转换 | 允许位置 |
|------|---------|
| 平台原始窗口位置 -> 逻辑窗口位置 | `normalize_platform_window_point()` 或等价统一入口 |
| 物理尺寸 -> 逻辑尺寸 | `logical_window_size_from_physical_size()` 或等价统一入口 |
| 逻辑绘制 -> 物理渲染 | 渲染后端结合 `RenderParams.scale_factor` |

一旦发现第二个“临时补丁式换算点”，应视为设计退化，必须回收。

### 8.4 事件链统一规范

新增鼠标相关能力时，必须保证：

1. hover、click、drag 起点使用同一窗口逻辑坐标语义。
2. 不同事件类型之间共享同一缓存位置或同一统一换算函数。
3. 不能让某个事件路径绕过 DPI 归一化。

### 8.5 平台特例管理规范

平台特例允许存在，但必须满足：

1. 特例只出现在平台边界。
2. 特例背后有运行时证据和自动化测试。
3. 特例必须在设计文档中记录原因和适用边界。
4. 特例不能泄漏到组件 API 层。

### 8.6 文档与测试同步规范

任何以下变更，都必须同步更新 D14 或引用 D14 的文档：

1. 修改 `normalize_platform_window_point()` 或平台归一化分支策略。
2. 修改 `WindowResized`、`ScaleFactorChanged` 或 `MouseEventCoords` 的单位语义。
3. 修改自动化 Harness 的 `*_platform_window_raw` / `*_logical` 注入约定。
4. 新增局部变换命中能力。

## 9. 变更实施流程

### 9.1 修复坐标问题的标准流程

1. 先判定症状归属：是输入坐标错误、交互区域错误，还是视觉位置与交互位置不同步。
2. 再画出坐标空间边界：平台原始值、归一化逻辑值、布局绝对位置、局部命中点、渲染变换后视觉位置。
3. 只找第一个错误转换点：重点排查重复 `/ scale_factor`、重复 `* scale_factor`、平移后未同步交互区域。
4. 补最小修复：优先收敛到统一转换入口，避免在单个 widget 上打补丁。
5. 补自动化回归：逻辑命中、平台原始窗口注入、1x/HiDPI 对照、局部坐标断言。
6. 回填文档：如果结论改变，必须更新 D14、D14a 与相关设计文档。

### 9.2 新平台接入流程

新增平台或更换窗口后端时，必须执行：

1. 标定平台返回的位置和尺寸到底属于哪种坐标空间。
2. 构造至少一个 1x 和一个 HiDPI 场景。
3. 用同一组件做 hover / click / replay 一致性验证。
4. 再决定是否复用现有 macOS / 非 macOS 分支策略。

### 9.3 引入局部变换能力的流程

1. 先定义视觉变换数据结构。
2. 再定义命中测试逆变换。
3. 再定义自动化注入语义。
4. 最后才开放业务组件使用。

## 10. 开发检查清单

以下清单是新增功能、修复和评审时必须执行的坐标语义门禁。

### 10.1 设计与建模检查

- [ ] 新增鼠标相关字段时，已明确它属于 `window_logical`、`local_logical`、`raw_window_position` 或新的独立坐标空间。
- [ ] 新增 API 没有复用模糊字段名 `position`、`x`、`y` 来同时表达多个参考系。
- [ ] 若需要平台特例，特例被收敛在平台边界，而不是泄漏到组件层、布局层或业务层。

### 10.2 实现检查

- [ ] 平台原始窗口坐标只通过 `normalize_platform_window_point()` 进入高层逻辑坐标。
- [ ] 组件层、命中测试、交互注册、事件处理全部消费逻辑坐标，不直接读取高层物理像素。
- [ ] `MouseMove`、`MouseDown`、`MouseUp`、`MouseWheel` 共享同一窗口逻辑坐标语义，没有重复 DPI 换算。
- [ ] 视觉平移、滚动或局部变换如影响交互，交互区域已同步更新或已实现逆变换。

### 10.3 测试与文档检查

- [ ] 至少验证一条逻辑注入链路和一条平台原始窗口注入链路，结果命中同一目标。
- [ ] 至少覆盖 `scale_factor = 1` 与 HiDPI 场景，确保 hover / click / replay 结果一致。
- [ ] 新增或变更坐标语义时，已同步更新 D14、迁移说明和受影响的设计文档引用。
- [ ] 评审结论已确认没有重新引入高层物理像素、平台特判扩散或坐标语义混用。

## 11. 验证标准

### 11.1 单元与集成验证

| 验证项 | 预期结果 |
|--------|---------|
| 平台输入归一化后进入 hover | hover 目标正确 |
| `MouseDown` / `MouseUp` 复用缓存逻辑位置 | click 目标与 hover 目标一致 |
| `WindowResized` 暴露逻辑尺寸 | 组件层不出现物理像素泄漏 |
| `ScaleFactorChanged` 后重算缓存鼠标位置 | 跨屏或 DPI 变化后命中仍正确 |
| 逻辑注入与平台原始窗口注入 | 命中、状态变化和事件坐标一致 |
| `scale_factor = 1` 与 HiDPI 交互一致 | hover / click / replay 结果一致 |
| macOS Retina 视觉点点击 | 能命中视觉目标，不出现左上角缩回偏移 |

### 11.2 文档化门禁

- [x] 当前坐标模型已明确区分逻辑像素、平台原始窗口坐标和渲染物理像素。
- [x] Qt 风格窗口坐标、局部坐标和原始输入证据已有正式术语。
- [x] 平台注入、逻辑注入与回放路径已有统一规范。
- [x] 组件局部变换的支持边界与禁止事项已明确记录。
- [x] 开发检查清单已纳入正式规范。

### 11.3 变更验收门禁

后续任何涉及鼠标坐标链路的 PR，至少满足：

1. 代码中不存在新的重复 DPI 换算点。
2. `scale_factor = 1` 与 HiDPI 对照测试通过。

4. 若引入新坐标空间，新增命名、注释、测试和迁移说明均已补齐。
